## 1. Mission: The Interface Is UP, but the Server Cannot Reach Its Destination

In JUN-046, you learned how Linux represents IPv4 and IPv6 addresses, how CIDR prefix notation works, and how addresses are associated with network interfaces.

You also learned that a correctly configured network interface does not automatically guarantee successful communication.

Now you will investigate two concepts that determine how a Linux host understands its network environment:

1. Subnets.
2. Default gateways.

Consider a production scenario.

An Ubuntu application server is configured with the following information:

```text
Hostname: app-server-01

Interface: ens3

IPv4 address: 192.168.10.20/24

Expected default gateway: 192.168.10.1

Remote database address: 192.168.20.30
```

The interface reports:

```text
<BROADCAST,MULTICAST,UP,LOWER_UP>
```

The IP address is present.

However, the application cannot communicate with the remote database.

The engineer inspects the server:

```bash
ip -4 route show
```

The output is:

```text
192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

There is no default route in the displayed IPv4 routing table.

What does this mean?

The server has a route associated with its directly connected subnet, but the displayed table contains no default route for destinations not covered by a more specific entry.

The remote database belongs to another subnet.

Unless another applicable routing rule or table supplies a path, the server has no matching route to that destination.

Your mission is to understand this behavior rather than immediately changing the gateway or restarting networking services.

By the end of this lab, you should be able to inspect an unfamiliar Linux host, determine its subnet boundaries, identify the role of its default gateway, investigate basic routing decisions, and explain why a destination is considered local or remote.

## 2. Understand What a Subnet Represents

A subnet is a defined portion of an IP address space.

Subnetting allows an organization to divide a larger address space into smaller network segments.

For example, an organization might use separate IPv4 subnets for:

- Application servers.
- Database servers.
- Management systems.
- Development environments.
- Monitoring infrastructure.

Consider the following conceptual architecture:

```text
                    ORGANIZATION NETWORK
                            |
                      L3 ROUTER / GATEWAY
                            |
              +-------------+-------------+
              |             |             |
              v             v             v
        APPLICATION      DATABASE      MANAGEMENT
           SUBNET         SUBNET         SUBNET

       192.168.10.0/24 192.168.20.0/24 192.168.30.0/24
              |             |             |
              v             v             v
        App Server       DB Server      Admin Host

       192.168.10.20   192.168.20.30   192.168.30.10
```

These addresses are part of different IPv4 subnets.

A host uses its addressing and routing configuration to determine how to send packets toward a destination.

### Why subnetting matters

Subnetting supports several engineering requirements.

**Address organization:** Infrastructure can be divided into understandable network ranges.

**Routing:** Routers and hosts can make forwarding decisions using network prefixes.

**Operational boundaries:** Teams can identify where applications and infrastructure components belong.

**Security architecture:** Subnets can form part of a wider segmentation design when combined with appropriate routing, firewall, and access-control policies.

**Infrastructure planning:** Network administrators can allocate address space according to capacity requirements.

However, subnetting alone does not automatically provide security isolation.

Actual isolation depends on the surrounding network and security configuration.

### Subnet versus physical network

A subnet is an IP-layer addressing concept.

It should not automatically be treated as identical to a physical Ethernet segment or VLAN.

Network designs can involve multiple IP prefixes on one link, virtual interfaces, overlays, and other arrangements.

For this junior lab, you will begin with a conventional design in which each subnet is associated with a distinct routed network segment.

## 3. Understand the Network and Host Portions of IPv4

Recall that an IPv4 address contains 32 bits.

Consider:

```text
192.168.10.20/24
```

The `/24` identifies the length of the network prefix.

This means:

```text
Total IPv4 bits: 32

Network prefix bits: 24

Remaining bits: 8
```

Conceptually:

```text
                32-BIT IPv4 ADDRESS

+--------------------------------+------------+
|       NETWORK PREFIX           | REMAINING  |
|           24 BITS              |   8 BITS   |
+--------------------------------+------------+
```

For this example, the network prefix identifies:

```text
192.168.10.0/24
```

### Binary representation

Convert the IPv4 address into binary:

```text
192       168       10        20

11000000.10101000.00001010.00010100
```

The `/24` prefix divides it after the first 24 bits:

```text
11000000.10101000.00001010 | 00010100
                             |
                        Prefix boundary
```

The first three octets belong to the network prefix.

The final eight bits form the remaining address portion.

### Important distinction

The IP address:

```text
192.168.10.20
```

and the prefix:

```text
/24
```

must be interpreted together.

Compare:

```text
192.168.10.20/24
```

with:

```text
192.168.10.20/28
```

Although the numerical address is identical, the network boundaries are different.

Never calculate a subnet using only the IP address while ignoring its prefix length.

## 4. Understand Subnet Masks and CIDR Notation

An IPv4 subnet mask is a 32-bit value used to identify the network prefix.

In a conventional subnet mask, the leading network bits are represented by binary ones, followed by binary zeros.

For example:

```text
CIDR: /24
```

Corresponding binary mask:

```text
11111111.11111111.11111111.00000000
```

Decimal representation:

```text
255.255.255.0
```

### Understand binary mask values

An eight-bit octet has these positional values:

```text
128  64  32  16  8  4  2  1
```

Consider:

```text
11111100
```

Calculate:

```text
128 + 64 + 32 + 16 + 8 + 4 = 252
```

Therefore:

```text
11111100 = 252
```

This is why a `/30` subnet mask ends with `252`.

### Common subnet masks

| CIDR prefix | Decimal subnet mask | Remaining IPv4 bits |
|---|---|---:|
| `/8` | 255.0.0.0 | 24 |
| `/16` | 255.255.0.0 | 16 |
| `/24` | 255.255.255.0 | 8 |
| `/25` | 255.255.255.128 | 7 |
| `/26` | 255.255.255.192 | 6 |
| `/27` | 255.255.255.224 | 5 |
| `/28` | 255.255.255.240 | 4 |
| `/29` | 255.255.255.248 | 3 |
| `/30` | 255.255.255.252 | 2 |
| `/31` | 255.255.255.254 | 1 |
| `/32` | 255.255.255.255 | 0 |

## 5. Calculate IPv4 Subnet Boundaries

You will now calculate network addresses and address ranges.

For a conventional IPv4 subnet, the important values include:

1. Network address.
2. Prefix length.
3. Total number of addresses.
4. Broadcast address.
5. Conventional usable host range.

### The address-count formula

For an IPv4 prefix:

```text
Remaining bits = 32 - Prefix length
```

The number of addresses in the block is:

```text
Total addresses = 2^(Remaining bits)
```

For example:

```text
/24
```

Remaining bits:

```text
32 - 24 = 8
```

Total addresses:

```text
2^8 = 256
```

For a conventional `/24` subnet, the network and broadcast addresses are not ordinarily assigned to individual hosts.

Therefore:

```text
Conventional usable host addresses = 256 - 2

                                  = 254
```

This subtraction is not a universal rule for every IPv4 prefix.

You will examine `/31` and `/32` separately.

### Worked Example A — Calculate a `/24`

Given:

```text
192.168.10.20/24
```

Subnet mask:

```text
255.255.255.0
```

Network address:

```text
192.168.10.0
```

Broadcast address:

```text
192.168.10.255
```

Conventional usable host range:

```text
192.168.10.1 – 192.168.10.254
```

Total addresses:

```text
256
```

Conventional usable host addresses:

```text
254
```

### Worked Example B — Calculate a `/26`

Given:

```text
192.168.10.70/26
```

Subnet mask:

```text
255.255.255.192
```

Remaining bits:

```text
32 - 26 = 6
```

Total addresses:

```text
2^6 = 64
```

A useful calculation is:

```text
Block size = 256 - 192

           = 64
```

The subnet boundaries in the final octet are:

```text
0
64
128
192
```

Therefore, the four `/26` blocks inside `192.168.10.0/24` are:

| Network address | Address range |
|---|---|
| `192.168.10.0/26` | `.0 – .63` |
| `192.168.10.64/26` | `.64 – .127` |
| `192.168.10.128/26` | `.128 – .191` |
| `192.168.10.192/26` | `.192 – .255` |

The address:

```text
192.168.10.70
```

belongs to:

```text
192.168.10.64/26
```

Its broadcast address is:

```text
192.168.10.127
```

Conventional usable host range:

```text
192.168.10.65 – 192.168.10.126
```

Total addresses:

```text
64
```

Conventional usable host addresses:

```text
62
```

### Worked Example C — Calculate a `/28`

Given:

```text
10.20.30.45/28
```

Subnet mask:

```text
255.255.255.240
```

Remaining bits:

```text
32 - 28 = 4
```

Total addresses:

```text
2^4 = 16
```

Block size:

```text
256 - 240 = 16
```

Relevant boundaries:

```text
0
16
32
48
64
...
```

The address `.45` falls between `.32` and `.47`.

Therefore:

```text
Network address: 10.20.30.32

Broadcast address: 10.20.30.47

Usable range: 10.20.30.33 – 10.20.30.46

Total addresses: 16

Conventional usable hosts: 14
```

## 6. Understand `/30`, `/31`, and `/32` Special Cases

A junior engineer should understand why the conventional usable-host formula has exceptions.

### `/30` subnet

A `/30` contains:

```text
2^(32 - 30) = 4 addresses
```

Example:

```text
192.0.2.0/30
```

Addresses:

```text
192.0.2.0 — Network address

192.0.2.1 — Conventional usable host

192.0.2.2 — Conventional usable host

192.0.2.3 — Broadcast address
```

This leaves two conventional usable addresses.

### `/31` subnet

A `/31` contains two IPv4 addresses.

Under RFC 3021, `/31` prefixes can be used on appropriate point-to-point links, allowing both addresses to serve as endpoint addresses.

Example:

```text
192.0.2.0/31
```

Endpoints:

```text
192.0.2.0

192.0.2.1
```

Do not blindly apply the conventional `total - 2` formula to this point-to-point use case.

### `/32` prefix

A `/32` identifies one IPv4 address.

Example:

```text
192.0.2.20/32
```

It is commonly used where an individual host address or specific routing destination must be represented.

### Engineering principle

Subnet calculations must account for the intended network design.

Memorizing:

```text
Usable hosts = 2^h - 2
```

without understanding the relevant exceptions can produce incorrect conclusions.

## 7. Determine Whether Two Addresses Belong to the Same Subnet

This is a core operational skill.

Consider:

```text
Host A: 192.168.10.20/24

Host B: 192.168.10.80/24
```

Both addresses belong to:

```text
192.168.10.0/24
```

Under a conventional directly connected design, Host A can treat Host B as an on-link destination.

Now consider:

```text
Host A: 192.168.10.20/24

Host C: 192.168.20.30/24
```

Host C belongs to:

```text
192.168.20.0/24
```

It is outside Host A's directly connected `/24` subnet.

A route through an appropriate next hop is normally required.

### Important: Do not compare only the first three octets

Consider:

```text
192.168.10.20/26

192.168.10.100/26
```

The first three octets are identical.

However:

```text
192.168.10.20
```

belongs to:

```text
192.168.10.0/26
```

while:

```text
192.168.10.100
```

belongs to:

```text
192.168.10.64/26
```

They are in different `/26` subnets.

### Practical Exercise 3 — Local or remote?

Assume the source host is:

```text
192.168.10.70/26
```

Its network is:

```text
192.168.10.64/26
```

Classify the following destinations relative to that subnet:

| Destination | Within the source subnet? |
|---|---|
| `192.168.10.80` | Yes |
| `192.168.10.100` | Yes |
| `192.168.10.126` | Yes |
| `192.168.10.130` | No |
| `192.168.10.20` | No |
| `192.168.20.10` | No |

The source subnet spans:

```text
192.168.10.64 – 192.168.10.127
```

Its conventional usable host range is:

```text
192.168.10.65 – 192.168.10.126
```

Notice that membership in the subnet and suitability as a conventional host address are related but distinct questions.

## 8. Understand What a Default Gateway Does

A default gateway is the next-hop router a host uses when an applicable route directs otherwise-unmatched destinations through that gateway.

Consider:

```text
Host IP: 192.168.10.20/24

Gateway: 192.168.10.1

Remote destination: 192.168.20.30
```

Conceptually:

```text
          APPLICATION SERVER
            192.168.10.20
                   |
                   |
          192.168.10.0/24
                   |
                   v
            DEFAULT GATEWAY
            192.168.10.1
                   |
                   v
             ROUTED NETWORK
                   |
                   v
            DATABASE SERVER
            192.168.20.30
```

The application server does not ordinarily send the remote packet directly to the database server's Ethernet MAC address across its local link.

Instead, it forwards the packet toward the selected next hop.

### What does `default` mean?

In an IPv4 routing table, a default route is represented by:

```text
0.0.0.0/0
```

A prefix length of zero matches every IPv4 destination.

However, Linux normally selects the most specific applicable route.

Therefore, a directly connected `/24` route takes precedence over a default `/0` route when both are otherwise applicable to a destination.

### Example routing table

```text
default via 192.168.10.1 dev ens3

192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

Interpretation:

**Route 1**

```text
default via 192.168.10.1 dev ens3
```

This supplies a default next hop through `192.168.10.1` using interface `ens3`.

**Route 2**

```text
192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

This identifies the directly connected IPv4 prefix associated with the interface.

### Important distinction

A default gateway is not necessarily the next hop for every destination.

A host can have:

- Directly connected routes.
- Static routes.
- Routes learned through other mechanisms.
- Multiple routing tables.
- Policy-routing rules.
- A default route.

This lab focuses on the conventional main-table routing arrangement.

More detailed route selection belongs to JUN-048.

## 9. Understand Gateway Addressing Requirements

A conventional Ethernet host generally needs an appropriate on-link path to its selected gateway.

Consider:

```text
Host: 192.168.10.20/24

Gateway: 192.168.10.1
```

The host's subnet is:

```text
192.168.10.0/24
```

The gateway address belongs to the same subnet.

This is a conventional configuration.

Now consider:

```text
Host: 192.168.10.20/24

Gateway: 192.168.20.1
```

The gateway address is outside the host's directly connected `/24` prefix.

Without an appropriate additional route or supported on-link configuration, this is not a conventional valid gateway arrangement.

### Why the gateway must be reachable

A next-hop router is useful only if the host can actually reach it through the selected networking arrangement.

A configured gateway address alone does not establish that the router exists or is functioning.

### Gateway versus DNS server

These two settings perform different jobs.

| Default gateway | DNS server |
|---|---|
| Provides a next hop for applicable routed traffic | Provides name-resolution services |
| Participates in packet forwarding | Resolves supported names into DNS records |
| Appears in routing configuration | Appears in resolver configuration |
| Does not automatically resolve domain names | Does not automatically act as the host's gateway |

Example:

```text
Host: 192.168.10.20/24

Default gateway: 192.168.10.1

DNS server: 192.168.10.53
```

These addresses serve different purposes.

Do not change DNS configuration to repair a confirmed missing default route unless separate evidence establishes an additional DNS problem.

## 11. Investigate Linux Route Selection with `ip route get`

A routing table shows available routes.

Sometimes you also need to know which route Linux would select for a particular destination.

The `ip route get` command is useful for this investigation.

It performs a route lookup and reports the selected routing information.

It does not send an application request to the destination or prove that the destination is reachable.

### Practical Task 6 — Inspect a local destination

First identify your own IPv4 address and prefix.

For illustration, assume your host uses:

```text
192.168.10.20/24
```

A possible local destination is:

```text
192.168.10.50
```

Run:

```bash
ip -4 route get 192.168.10.50
```

Representative output:

```text
192.168.10.50 dev ens3 src 192.168.10.20 uid 1000
    cache
```

Interpretation:

Linux selected interface `ens3` for this destination and identified `192.168.10.20` as the source address.

The exact output depends on your system.

### Practical Task 7 — Inspect a remote destination

Using the same illustrative host, run:

```bash
ip -4 route get 198.51.100.20
```

Representative output:

```text
198.51.100.20 via 192.168.10.1 dev ens3 src 192.168.10.20 uid 1000
    cache
```

This shows that Linux selected the gateway as the next hop.

The destination belongs to a documentation range and is used here only for route-lookup illustration.

Do not interpret the result as proof that the destination is actually accessible.

### Important environment consideration

Your real host may use a different address range, default route, or routing policy.

For a local-route exercise, select an appropriate destination based on your actual configured prefix.

Do not assume `192.168.10.50` is local to every Ubuntu machine.

### What if there is no matching route?

A route lookup may fail with an error such as:

```text
RTNETLINK answers: Network is unreachable
```

This indicates that the lookup did not find a usable route under the applicable routing configuration.

However, a route-lookup failure should still be interpreted in the context of the requested destination, address family, routing rules, and network namespace.

### Verification

Record:

```text
Destination tested:

Selected outgoing interface:

Selected source address:

Next-hop gateway displayed?:

Did the lookup succeed?:

What does the result establish?:

What does it NOT establish?:
```

A correct answer to the final question should mention that route selection does not independently verify successful packet delivery or application connectivity.

## 12. Understand the IPv6 Equivalent

IPv6 also uses network prefixes and routing.

However, IPv6 addressing has important differences from conventional IPv4 subnet calculations.

Consider:

```text
2001:db8:10:20::15/64
```

The prefix length is:

```text
/64
```

IPv6 contains 128 bits.

Therefore:

```text
Prefix bits: 64

Remaining bits: 64
```

### IPv6 subnet representation

Conceptually:

```text
                128-BIT IPv6 ADDRESS

+--------------------------------+--------------------------------+
|       NETWORK PREFIX           |       REMAINING BITS           |
|           64 BITS              |           64 BITS              |
+--------------------------------+--------------------------------+
```

### IPv6 does not use IPv4-style broadcast

Do not apply conventional IPv4 broadcast-address calculations to IPv6.

IPv6 uses multicast and other mechanisms instead of IPv4-style broadcast addressing.

### IPv6 default route

An IPv6 default route is represented by:

```text
::/0
```

A Linux routing table may show:

```text
default via fe80::1 dev ens3
```

The gateway may use an IPv6 link-local address.

Because link-local addresses are scoped to a link, the associated interface is important.

### Practical Task 8 — Inspect IPv6 configuration

Run:

```bash
ip -6 addr show
```

Then:

```bash
ip -6 route show
```

Look for:

- IPv6 addresses.
- Prefix lengths.
- Link-local addresses.
- Directly connected IPv6 prefixes.
- An IPv6 default route, if configured.

### Important distinction

The absence of a globally scoped IPv6 address or IPv6 default route does not automatically mean that the host's IPv4 networking is broken.

Your environment may intentionally use IPv4 only, dual-stack networking, or another supported configuration.

Do not enable IPv6 or modify its routes merely to reproduce an example.

## 13. Recognize Common Subnet and Gateway Problems

You should now be able to distinguish several common configuration problems.

### Problem 1 — Incorrect subnet mask

Expected:

```text
192.168.10.20/24
```

Observed:

```text
192.168.10.20/28
```

The numerical IP address is the same, but the subnet boundaries differ.

With `/28`, the address belongs to:

```text
192.168.10.16/28
```

The conventional usable range is:

```text
192.168.10.17 – 192.168.10.30
```

An expected gateway at `192.168.10.1` is outside that directly connected `/28` subnet.

This discrepancy requires investigation against the approved network design.

### Problem 2 — Missing default route

The routing table contains:

```text
192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

but no applicable default route or other route to a remote destination.

Local subnet communication may still be possible, while communication to other prefixes can fail.

### Problem 3 — Incorrect default gateway

Expected:

```text
192.168.10.1
```

Observed:

```text
192.168.10.254
```

Both addresses may belong to the same subnet.

However, subnet membership alone does not prove that either address is the correct router.

Compare the configuration with approved infrastructure records.

### Problem 4 — Gateway outside the directly connected prefix

Host:

```text
192.168.10.20/24
```

Gateway:

```text
192.168.20.1
```

Without a suitable additional route or on-link configuration, the gateway is not directly reachable through the conventional connected `/24` arrangement.

### Problem 5 — Assuming two hosts are local because their first three octets match

Consider:

```text
192.168.10.20/26

192.168.10.100/26
```

They belong to different `/26` prefixes.

Always calculate the actual network boundaries.

### Problem 6 — Treating a default route as proof of Internet connectivity

A route such as:

```text
default via 192.168.10.1 dev ens3
```

establishes a configured routing path.

It does not prove that the gateway is operational, forwarding is permitted, upstream routing exists, or the destination application is available.

### Problem 7 — Confusing DNS with gateway configuration

A DNS server resolves names.

A gateway participates in packet forwarding.

Do not change one simply because the other appears to be failing.

### Problem 8 — Assuming every host needs a default gateway

Some intentionally isolated hosts have only directly connected or explicitly defined routes.

Whether a default route is required depends on the intended network design.

### Problem 9 — Assuming the main routing table describes every possible routing decision

Advanced Linux systems can use multiple routing tables and policy-routing rules.

The ordinary `ip route show` view is useful, but it should not be treated as an exhaustive description of every possible network configuration.

Detailed policy routing is outside this junior lab.

## 14. Controlled Failure Lab — The Missing Default Gateway

This section follows the engineering investigation sequence:

**Learn → Do → Break → Investigate → Fix → Verify**

The failure is simulated using supplied evidence.

Do not delete the default route on your actual machine.

### Production scenario

An Ubuntu application server is expected to communicate with a database server on another subnet.

Approved configuration:

```text
Application server:

Interface: ens3

IPv4 address: 192.168.10.20/24

Default gateway: 192.168.10.1


Database server:

IPv4 address: 192.168.20.30
```

The approved network architecture is:

```text
          APPLICATION SERVER
            192.168.10.20
                  |
                  |
           192.168.10.0/24
                  |
                  v
           DEFAULT GATEWAY
            192.168.10.1
                  |
                  v
            ROUTED NETWORK
                  |
                  v
            DATABASE SUBNET
           192.168.20.0/24
                  |
                  v
            DATABASE SERVER
            192.168.20.30
```

### Phase 1 — Learn the expected behavior

The application server belongs to:

```text
192.168.10.0/24
```

The database belongs to:

```text
192.168.20.0/24
```

They are different subnets.

The approved design requires the application server to forward appropriate remote traffic through:

```text
192.168.10.1
```

### Phase 2 — Do: inspect the supplied baseline

Before the incident, the routing table contained:

```text
default via 192.168.10.1 dev ens3

192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

The default route provided a next hop for the database destination.

### Phase 3 — Break: simulated failure injection

During an unauthorized configuration change, the default route was removed.

The current routing table is:

```text
192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

The interface remains administratively enabled.

Its IP address is unchanged.

The failure is confined to the supplied incident scenario.

### Phase 4 — Investigate

**Symptom**

The application cannot communicate with the remote database.

**Impact**

Application functionality that depends on the database is unavailable.

**Evidence A — Interface state**

```text
ens3: <BROADCAST,MULTICAST,UP,LOWER_UP>
```

The interface reports an operational lower-layer connection.

**Evidence B — Address configuration**

```text
inet 192.168.10.20/24 scope global ens3
```

The address matches the approved configuration.

**Evidence C — Routing table**

```text
192.168.10.0/24 dev ens3 proto kernel scope link src 192.168.10.20
```

The expected default route is missing.

**Evidence D — Destination comparison**

Source subnet:

```text
192.168.10.0/24
```

Destination:

```text
192.168.20.30
```

The destination is outside the source subnet.

### Phase 5 — Form and test the hypothesis

Hypothesis:

> The application server cannot select an appropriate route to the database because its expected default route is missing.

The engineer performs a route lookup:

```bash
ip -4 route get 192.168.20.30
```

In the supplied simplified environment, the result is:

```text
RTNETLINK answers: Network is unreachable
```

This supports the missing-route hypothesis.

The infrastructure team confirms that no other applicable route or policy-routing arrangement provides a path to the database.

### Phase 6 — Identify the root cause

The confirmed root cause is the unauthorized removal of the application server's default route.

The evidence does not support changing DNS, replacing the interface, or restarting the application as the primary corrective action.

### Phase 7 — Determine the fix

The authorized engineer restores the approved default-route configuration through the supported persistent network-management process.

For Ubuntu Server, this may involve the environment's managed networking configuration, such as Netplan, depending on how the host is provisioned.

The correction must be reviewed for compatibility with existing routes, address configuration, and remote management.

Do not apply a temporary command blindly and assume the configuration will survive a reboot.

### Phase 8 — Recovery verification

After the approved correction, the engineer repeats:

```bash
ip -4 route show
```

Expected evidence includes:

```text
default via 192.168.10.1 dev ens3
```

The engineer then repeats:

```bash
ip -4 route get 192.168.20.30
```

A representative successful lookup is:

```text
192.168.20.30 via 192.168.10.1 dev ens3 src 192.168.10.20
```

This verifies that the expected route is selected.

However, it does not independently prove that the database application is reachable.

The original application communication test must also be repeated using an approved method.

### Phase 9 — Prevention

Recommended operational controls include:

- Review of network configuration changes.
- Version-controlled infrastructure configuration.
- Approved gateway baselines.
- Post-change routing verification.
- Monitoring for unexpected route removal.
- Documented recovery procedures.
- Validation of application connectivity after network maintenance.

### Incident report


### Engineering lesson

Do not classify every network failure as an interface failure.

The interface, IP address, subnet, gateway, route, and application are different components of the communication path.

Investigate them individually.

## 17. Knowledge Check and Interview Preparation

### Knowledge Check

Answer these questions without immediately returning to the explanations.

**1. What is a subnet?**

A defined portion of an IP address space identified by a network prefix.

**2. How many bits are in IPv4?**

32 bits.

**3. What does `/24` mean?**

The network prefix contains 24 bits.

**4. What subnet mask corresponds to `/26`?**

`255.255.255.192`.

**5. How many addresses exist in a `/27` block?**

32 addresses.

**6. What is the conventional usable host count for `/28`?**

14.

**7. What is the network address of `192.168.10.70/26`?**

`192.168.10.64`.

**8. What is the broadcast address of that subnet?**

`192.168.10.127`.

**9. What is the conventional usable range of `192.168.10.64/26`?**

`192.168.10.65–192.168.10.126`.

**10. What is a default gateway?**

A next-hop router used by an applicable default route for destinations not covered by a more specific selected route.

**11. What IPv4 prefix represents the default route?**

`0.0.0.0/0`.

**12. What IPv6 prefix represents the default route?**

`::/0`.

**13. Does every packet automatically use the default gateway?**

No. More specific applicable routes can be selected.

**14. What command displays IPv4 routes?**

`ip -4 route show`.

**15. What command investigates the selected route to an IPv4 destination?**

`ip -4 route get DESTINATION`.

**16. Does a successful route lookup prove that a remote service is reachable?**

No.

**17. Why is the conventional `total - 2` usable-host calculation not universally applicable?**

Appropriate `/31` point-to-point configurations and `/32` individual-address prefixes require different interpretation.

**18. Does IPv6 use IPv4-style broadcast addressing?**

No.

**19. Can an IPv6 default router use a link-local address?**

Yes.

**20. Why should an engineer avoid removing the default route on a remote server?**

It can interrupt remote connectivity and application communication.

### Interview Practice

#### 1. How do you determine the subnet of an IPv4 address?

I identify the prefix length, derive the subnet mask, and calculate the network address using the network-prefix bits. I then determine the address block boundaries and conventional usable range where applicable.

#### 2. What is the difference between an IP address and a subnet mask?

The IP address identifies an endpoint in an IP networking context. The subnet mask identifies which bits belong to the network prefix in conventional IPv4 notation.

#### 3. What is the default gateway used for?

It provides a next hop for traffic when the selected default route applies and no more specific applicable route takes precedence.

#### 4. How do you find the default gateway on Ubuntu?

I inspect the IPv4 routing table:

```bash
ip -4 route show
```

A conventional default route may appear as:

```text
default via 192.168.10.1 dev ens3
```

#### 5. How would you investigate whether Linux has a route to a destination?

I would use:

```bash
ip -4 route get 198.51.100.20
```

I would inspect the selected interface, source address, and next hop, if present.

#### 6. A server has the correct IP address but cannot reach another subnet. What would you check?

I would calculate the source subnet, confirm the destination is outside it, inspect the relevant routes and gateway configuration, and compare the running configuration with the approved design.

#### 7. Why might two addresses with the same first three octets belong to different subnets?

Because subnet membership depends on the configured prefix length, not simply on matching decimal octets.

For example, `192.168.10.20/26` and `192.168.10.100/26` belong to different `/26` subnets.

#### 8. What is the difference between a default gateway and a DNS server?

A gateway participates in forwarding traffic toward routed destinations. A DNS server provides name-resolution services. They serve different purposes.
