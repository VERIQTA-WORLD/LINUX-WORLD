# JUN-001: Linux Terminal Navigation

- **Level:** Junior
- **Difficulty:** 1/5
- **Estimated time:** 30–45 minutes
- **Environment:** One Ubuntu Server 24.04 LTS system or VM
- **Privileges:** Standard user account
- **Cost:** Free with a local VM
- **Primary skill:** Linux terminal navigation

---

## Lab Mission

You have logged in to a Linux server and need to become comfortable moving around without relying on a graphical file manager.

That may sound simple, but navigation is one of the habits everything else in Linux builds on. Before you can work with configuration files, inspect logs, manage services, troubleshoot applications, or write automation, you need to know where you are and how to get where you need to go.

In this lab, you will learn how to inspect your current location, move between directories, work with absolute and relative paths, recognize important path symbols, and recover when you navigate to the wrong place.

By the end, you should be able to move around a Linux system deliberately instead of guessing your way through the filesystem.

---

## What you will learn

By completing this lab, you should be able to:

* Identify your current working directory.
* List the contents of a directory.
* Move between directories with `cd`.
* Recognize the filesystem root and your home directory.
* Understand `.`, `..`, and `~`.
* Distinguish between absolute and relative paths.
* Return to your previous working directory.
* Display hidden files and directories.
* Inspect another directory without moving into it.
* Recognize and investigate common navigation errors.
* Verify your location after moving through the filesystem.

This is the first Linux World lab, so there are no previous labs to complete.

You only need access to a Linux terminal and a standard user account. `sudo` is not required.

## Before you begin

The examples in this lab use Ubuntu Server 24.04 LTS, but the commands are common across Linux distributions.

You may see examples containing a username such as:

```text
student
```

Your username will probably be different. Use your own environment as it is. There is no need to rename anything to match the examples.

This is also a low-risk lab. You will work mainly inside your home directory and will not modify system configuration, install packages, change permissions, or restart services.

# 1. Start with the terminal

When you open a terminal or connect to a Linux server through SSH, you are given a command-line environment.

You may see a prompt similar to:

```text
student@linux-server:~$
```

The exact appearance varies between systems.

In this example:

* `student` is the username.
* `linux-server` is the hostname.
* `~` represents the user's home directory.
* `$` commonly indicates that you are using a regular user account.

The prompt itself is not something you type.

You type commands after it.

For example:

```bash
pwd
```

The shell interprets the command, Linux performs the requested operation, and the result is displayed in the terminal.

You do not need to understand the shell in detail yet. Bash and shell behavior are covered later in Linux World.

For now, think of the terminal as the place where you interact with Linux using commands.

---

# 2. Find out where you are

Before moving anywhere, find your current location.

Run:

```bash
pwd
```

`pwd` stands for **print working directory**.

You may see something similar to:

```text
/home/student
```

Your actual path depends on your username and environment.

The important idea is that your shell always has a **current working directory**.

When you move through the filesystem, that working directory changes.

Get into the habit of using `pwd` whenever you are unsure where you are.

### Checkpoint

Run:

```bash
pwd
```

Look at the output and make sure you can answer one simple question:

**Where am I right now?**

Do not continue based on where you think you are. Use the output from the system.

---

# 3. Look around

Once you know where you are, the next question is usually:

**What is here?**

Run:

```bash
ls
```

`ls` lists the contents of a directory.

Depending on your environment, you might see something like:

```text
Desktop  Documents  Downloads
```

A minimal server installation may contain fewer entries. You may even receive no visible output if the directory contains no visible files or directories.

That does not necessarily mean something went wrong.

Try:

```bash
ls -l
```

The `-l` option asks `ls` for a long listing.

You may see something similar to:

```text
drwxr-xr-x 2 student student 4096 Sep 24 10:15 Documents
```

There is a lot of information in that line.

You do not need to understand it all yet. Ownership and permissions have their own labs later in the Junior curriculum.

For now, notice the difference between `ls` and `ls -l`.

One gives you a simple listing. The other gives you more information about what is there.

### Engineer Note

A command returning no visible output does not automatically mean it failed.

For example, `ls` may display nothing because there are no visible entries in the directory.

Learning to distinguish **no output** from **an error** is an important command-line habit.

# 4. Understand the filesystem root

Linux organizes files and directories in a hierarchy.

At the top of that hierarchy is:

```text
/
```

This is the filesystem **root directory**.

A very simplified view looks like this:

```text
/
├── etc
├── home
│   └── student
├── tmp
├── usr
└── var
```

Your actual system contains more directories.

For now, the important thing is understanding that everything exists somewhere beneath `/`.

There is also an important distinction between:

```text
/
```

and:

```text
~
```

They are not the same thing.

`/` represents the top of the Linux filesystem.

`~` represents your home directory.

For a user named `student`, the home directory would commonly be:

```text
/home/student
```

So:

```text
/
```

means the filesystem root, while:

```text
/home/student
```

is one location inside that filesystem.

You will use both constantly as you work with Linux.

---

## A note about the word "root"

Linux uses the word `root` in several related ways.

`/` is the filesystem root.

`root` is also the name of the administrative superuser.

`/root` is commonly that user's home directory.

You do not need to explore the root account in this lab. Just be careful not to assume that `/`, `/root`, and the `root` user all mean exactly the same thing.

# 6. Move between directories with `cd`

The command you will use to move between directories is:

```bash
cd
```

It means **change directory**.

Start by moving into your Linux World directory:

```bash
cd ~/linux-world-labs
```

Now check:

```bash
pwd
```

Your path should end with:

```text
/linux-world-labs
```

Move one level deeper:

```bash
cd JUN-001
```

Check again:

```bash
pwd
```

Now move into:

```bash
cd navigation
```

Check your location:

```bash
pwd
```

Finally:

```bash
cd practice
```

And verify:

```bash
pwd
```

Your path should now end with:

```text
/linux-world-labs/JUN-001/navigation/practice
```

Notice that you did not have to type the complete path every time.

That brings us to one of the most important ideas in Linux navigation.

---

# 7. Relative paths

When you ran:

```bash
cd JUN-001
```

Linux interpreted `JUN-001` from wherever you were currently located.

If you were in:

```text
/home/student/linux-world-labs
```

then `JUN-001` meant:

```text
/home/student/linux-world-labs/JUN-001
```

This is a **relative path**.

A relative path is interpreted from your current working directory.

That means the same relative path may work from one location and fail from another.

You will deliberately test that later in the lab.

---

# 8. Absolute paths

An absolute path starts from the filesystem root `/`.

For example:

```text
/etc
```

is an absolute path.

So is:

```text
/var/log
```

And:

```text
/home/student
```

Absolute paths begin with `/`.

Try moving to `/etc`:

```bash
cd /etc
```

Now verify:

```bash
pwd
```

You should see:

```text
/etc
```

List some of its contents:

```bash
ls
```

You will probably see many files and directories.

Do not modify them.

`/etc` contains system configuration, and at this stage you are only learning how to navigate.

Being able to reach a directory does not mean you should change what is inside it.

---

# 9. Absolute paths and relative paths side by side

Suppose you are currently here:

```text
/home/student/linux-world-labs
```

You could move into JUN-001 with:

```bash
cd JUN-001
```

That is a relative path.

You could also use:

```bash
cd /home/student/linux-world-labs/JUN-001
```

That is an absolute path.

The first depends on your current location.

The second begins from `/` and describes the location from the top of the filesystem.

There is no rule that says you must always use one or the other.

Both are useful.

What matters is understanding what Linux will interpret when you enter the path.

# 10. Your home directory

You do not need to type your full home path every time you want to return home.

Run:

```bash
cd ~
```

Then:

```bash
pwd
```

You should be back in your home directory.

There is an even shorter version:

```bash
cd
```

When used without a path, `cd` normally returns you to your home directory.

Try it:

```bash
cd /etc
pwd
cd
pwd
```

The first `pwd` should show `/etc`.

The second should show your home directory.

This is useful when you have moved deep into the filesystem and simply want to return to a familiar starting point.

# 11. Move to the parent directory

There are two special path references you need to know early:

```text
.
..
```

A single dot:

```text
.
```

represents the current directory.

Two dots:

```text
..
```

represent the parent directory.

Return to the practice directory:

```bash
cd ~/linux-world-labs/JUN-001/navigation/practice
```

Check:

```bash
pwd
```

Now move up one level:

```bash
cd ..
```

Check again:

```bash
pwd
```

You should now be inside `navigation`.

Run:

```bash
cd ..
```

again.

You should now be inside `JUN-001`.

You are moving upward through the directory hierarchy.

---

## What does `.` do?

Check your current location:

```bash
pwd
```

Now run:

```bash
cd .
```

Then check again:

```bash
pwd
```

Nothing changed.

That is expected.

`.` means the current directory, so you effectively told the shell to change into the directory it was already using.

It may not seem particularly useful yet, but you will encounter `.` frequently later when working with commands, scripts, and paths.

For now, remember:

```text
.     current directory
..    parent directory
```

---

# 12. Move through more than one level

You do not have to move one directory at a time.

Return home:

```bash
cd
```

Now go directly to the practice directory:

```bash
cd linux-world-labs/JUN-001/navigation/practice
```

Verify:

```bash
pwd
```

From there, run:

```bash
cd ../..
```

Then:

```bash
pwd
```

You should now be inside `JUN-001`.

Why?

You started here:

```text
JUN-001/navigation/practice
```

The first `..` moved you from `practice` to `navigation`.

The second moved you from `navigation` to `JUN-001`.

This is one of the reasons understanding the directory hierarchy matters more than simply memorizing `cd`.

# 13. Return to the previous directory

There is another useful form of `cd`:

```bash
cd -
```

This commonly switches back to your previous working directory.

Try:

```bash
cd /etc
```

Check:

```bash
pwd
```

Now return home:

```bash
cd ~
```

Check again:

```bash
pwd
```

Now run:

```bash
cd -
```

You should return to `/etc`.

Run:

```bash
cd -
```

again and you should return to your home directory.

This is particularly useful when you are repeatedly moving between two locations.

# 14. Hidden files and directories

Return home:

```bash
cd
```

Run:

```bash
ls
```

Now run:

```bash
ls -a
```

The second command will probably show more entries.

Linux commonly treats names beginning with a dot as hidden entries.

You may see:

```text
.bashrc
.profile
.ssh
```

Your system may contain different entries.

You will also notice:

```text
.
..
```

Those should now look familiar.

`.` represents your current directory.

`..` represents its parent.

### Common mistake

If `ls` does not display something, do not immediately conclude that it does not exist.

It may simply be hidden.

For example, `.bashrc` normally does not appear in a basic:

```bash
ls
```

but may appear with:

```bash
ls -a
```

Check the system before drawing a conclusion.

---

# 15. Inspect a directory without moving into it

You do not need to `cd` into every directory you want to inspect.

From your home directory, run:

```bash
ls /etc
```

Now check your location:

```bash
pwd
```

You are still in your home directory.

`ls /etc` asked Linux to show the contents of `/etc`.

It did not ask Linux to make `/etc` your working directory.

Compare:

```bash
cd /etc
```

with:

```bash
ls /etc
```

The first changes your current working directory.

The second inspects `/etc` without changing your location.

This distinction becomes very useful when you start troubleshooting systems.

# 16. When navigation goes wrong

So far, most of your commands have been designed to work.

Real terminal sessions are not like that.

Paths are mistyped. You start from the wrong location. A directory is not where you expected it to be.

The important skill is not avoiding every mistake.

It is learning how to investigate one.

Return home:

```bash
cd
```

Now deliberately run:

```bash
cd linux-world-labs/JUN-001/does-not-exist
```

You should receive an error similar to:

```text
bash: cd: linux-world-labs/JUN-001/does-not-exist: No such file or directory
```

The exact wording can vary slightly depending on your shell.

Do not immediately start changing the command at random.

First establish where you are:

```bash
pwd
```

Then inspect the location where you expected the directory to exist:

```bash
ls ~/linux-world-labs/JUN-001
```

You should discover that `does-not-exist` is not there.

The problem is not mysterious. The path points to a directory that does not exist.

Use the path that actually exists:

```bash
cd ~/linux-world-labs/JUN-001/navigation
```

Then verify:

```bash
pwd
```

And:

```bash
ls
```

You should see:

```text
practice
```

That is a very simple troubleshooting exercise, but the process matters:

**Observe the error → establish your current state → inspect the evidence → identify the cause → correct it → verify.**

You will use that pattern throughout Linux World.

---

# 17. A relative path from the wrong location

Here is another common problem.

Move to:

```bash
cd /etc
```

Now try:

```bash
cd linux-world-labs/JUN-001
```

The command should fail.

Why?

Check:

```bash
pwd
```

You are in:

```text
/etc
```

Because you supplied a relative path, Linux is looking for `linux-world-labs/JUN-001` relative to `/etc`.

That is not where you created it.

You have several ways to correct the problem.

You could return home first:

```bash
cd
cd linux-world-labs/JUN-001
```

Or you could use your home directory directly:

```bash
cd ~/linux-world-labs/JUN-001
```

Then verify:

```bash
pwd
```

The lesson is not that relative paths are bad.

The lesson is that relative paths depend on where you are.

---

## Engineer Note

When a path fails, repeatedly editing the command until something works is not troubleshooting.

Start with facts.

```bash
pwd
ls
```

Ask where you are, what exists there, and whether the path you supplied makes sense from that location.

This habit becomes much more important when the problem is a failed service or production outage instead of a missing directory.

---

# 18. A few things that commonly go wrong

Most early navigation problems come from simple causes:

* The directory name was typed incorrectly.
* The capitalization is wrong.
* You started from the wrong directory.
* You confused a relative path with an absolute path.
* The entry is hidden.
* The target does not exist.
* You are trying to enter something that is not a directory.
* Your user does not have permission to access the location.

Linux names are case-sensitive.

These can be different names:

```text
Documents
documents
DOCUMENTS
```

Do not expect Linux to silently correct the capitalization.

Another habit to avoid is reaching for `sudo` whenever something fails.

A failed `cd` does not automatically mean you need more privileges. The path may simply be wrong.

First investigate the actual error.
