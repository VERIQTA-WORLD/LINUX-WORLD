# JUN-003: Files and Directories

- **Level:** Junior
- **Difficulty:** 1/5
- **Estimated time:** 45–60 minutes
- **Environment:** Ubuntu Server 24.04 LTS or a similar Linux system
- **Privileges:** Standard user account
- **Primary skills:** Understanding files, directories, file types and filesystem structure
- **Prerequisites:** JUN-001 and JUN-002

---

## Lab Mission

Almost everything you work with on a Linux system eventually leads you back to the filesystem.

Configuration lives in files. Logs are stored in files. Applications use files. Users have home directories. Services read configuration from directories such as `/etc`. System information is exposed through filesystem-like interfaces such as `/proc`. Devices can even appear as special files under `/dev`.

Before you start creating, copying, moving and deleting files in the next lab, you need to understand what you are actually working with.

In this lab, you will explore the Linux filesystem and learn how to distinguish files from directories, recognize different file types, inspect metadata, understand naming rules, identify hidden files and investigate paths safely.

The objective is not to memorize every directory on Linux.

It is to become comfortable looking at an unfamiliar filesystem and working out what is there.

---

## What you will learn

By the end of this lab, you should be able to:

* Explain the difference between a file and a directory.
* Understand how Linux organizes files in a single filesystem hierarchy.
* Recognize common top-level Linux directories.
* Distinguish regular files, directories and symbolic links.
* Use `ls` to inspect filesystem objects.
* Use `file` to investigate what a file contains or represents.
* Use `stat` to inspect file metadata.
* Recognize hidden files and directories.
* Understand basic Linux filename rules.
* Recognize absolute and relative paths in context.
* Inspect important system directories without modifying them.
* Investigate common file and directory errors.
* Verify whether a path refers to the object you expected.

# 1. Start with the filesystem

Linux organizes files and directories in a hierarchy.

At the top is:

```text
/
```

This is the filesystem root.

Everything else is located somewhere beneath it.

A simplified Linux filesystem might look like this:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
│   └── student
├── opt
├── proc
├── root
├── run
├── srv
├── sys
├── tmp
├── usr
└── var
```

Your system may contain additional directories.

Some entries may also be implemented differently from what this simplified diagram suggests. For example, on modern Ubuntu systems, directories such as `/bin` may be symbolic links into `/usr`.

You do not need to memorize this tree.

You need to understand the model:

```text
/
└── directories
    ├── files
    ├── more directories
    │   ├── files
    │   └── more directories
    └── other filesystem objects
```

There is one hierarchy beginning at `/`.

# 3. What is a file?

At the simplest level, a file is a named filesystem object that can contain data.

A text document can be a file.

A configuration can be a file.

A shell script can be a file.

A log can be a file.

An executable program can be stored in a file.

For example:

```text
/etc/hostname
```

is commonly a regular file containing the system's hostname configuration.

Check whether it exists:

```bash
ls -l /etc/hostname
```

If it exists on your system, you should receive one listing for that path.

You do not need to modify it.

The important thing is that `/etc/hostname` identifies one filesystem object at a specific location.

---

# 4. What is a directory?

A directory is used to organize filesystem entries.

You can think of it as part of the structure that allows Linux to organize paths.

For example:

```text
/etc
```

is a directory.

Inside it are many files and subdirectories.

Inspect it:

```bash
ls /etc
```

Now compare:

```bash
ls -ld /etc
```

with:

```bash
ls -l /etc
```

These commands do something different.

```bash
ls -l /etc
```

lists the contents of `/etc` in long format.

```bash
ls -ld /etc
```

shows information about the `/etc` directory entry itself rather than listing its contents.

That difference is useful when you want to inspect the directory rather than everything inside it.

# 5. Files and directories are identified by their paths

Consider:

```text
/etc/hostname
```

The final component:

```text
hostname
```

is located inside:

```text
/etc
```

which is located beneath:

```text
/
```

You can mentally read the path as:

```text
/
└── etc
    └── hostname
```

Now consider:

```text
/home/student/Documents/report.txt
```

Conceptually:

```text
/
└── home
    └── student
        └── Documents
            └── report.txt
```

The exact path to your home directory depends on your username and environment.

Check yours:

```bash
pwd
```

Then:

```bash
ls -ld ~
```

Your home directory is itself an object inside the larger Linux filesystem hierarchy.

# 6. A filename does not have to contain an extension

If you come from an operating system where extensions such as `.txt`, `.jpg` or `.exe` are heavily emphasized, Linux may initially feel different.

Linux filenames can contain extensions, but an extension is not required for something to be a file.

Examples of filenames you may encounter include:

```text
hostname
passwd
hosts
.profile
notes.txt
backup.tar.gz
deploy.sh
```

These are all names.

The characters after a dot may communicate useful information to people and applications, but Linux does not universally determine a file's true content simply from the extension.

For example:

```text
notes.txt
```

suggests a text file.

But the name alone does not prove what the file contains.

That is one reason Linux provides tools such as `file`.

# 7. Ask Linux what a file is

Run:

```bash
file /etc/hostname
```

Depending on your system and the contents of the file, you may see a description indicating text data.

Now try:

```bash
file /etc/passwd
```

Then:

```bash
file /bin/ls
```

On modern Ubuntu, `/bin/ls` may resolve through a symbolic link into `/usr/bin`, but `file` should identify the target as an executable binary.

The exact output can vary between systems and versions.

Do not memorize the wording.

Focus on what `file` is doing:

**It examines the object and reports what kind of data it appears to contain or represent.**

Try:

```bash
file /etc
```

You should see that `/etc` is a directory.

Now compare:

```bash
file /etc
file /etc/hostname
file /bin/ls
```

You have inspected three very different filesystem objects.

# 8. Names can be misleading

Suppose somebody gives you a file called:

```text
server.conf
```

The name suggests configuration.

But a filename is not proof of content.

The same applies to:

```text
report.txt
```

or:

```text
image.jpg
```

A person can give a file almost any valid name.

That is why engineers inspect rather than assume.

Later you will learn additional ways to examine file contents safely.

For now, remember:

**The filename gives you a clue. It does not guarantee what is inside.**

# 9. Inspect metadata with `stat`

Sometimes you want more information about a filesystem object than `ls` gives you.

Run:

```bash
stat /etc/hostname
```

You should see metadata about the file.

Depending on your system, this may include information such as:

* File size
* Blocks
* File type
* Device information
* Inode number
* Links
* Access permissions
* User and group ownership
* Access time
* Modification time
* Metadata change time

You do not need to understand all of those fields yet.

Several have dedicated labs later.

For now, notice that a file has more associated information than its name and contents.

Now inspect a directory:

```bash
stat /etc
```

Compare the result with:

```bash
stat /etc/hostname
```

One describes a directory.

The other describes a regular file.

# 10. Regular files and directories are not the only object types

Linux filesystems can contain several kinds of objects.

You will encounter these gradually throughout Linux World.

Common examples include:

* Regular files
* Directories
* Symbolic links
* Character devices
* Block devices
* Named pipes
* Sockets

You do not need to master all of them in this lab.

At this point, concentrate on three:

```text
regular file
directory
symbolic link
```

Regular files store ordinary data.

Directories organize filesystem entries.

Symbolic links refer to another path.

Symbolic links receive their own dedicated treatment in JUN-034. Here, you only need to be able to recognize one when you encounter it.

# 11. Recognize object types in `ls -l`

Run:

```bash

```

Look at the first character on each output line.

You may see entries beginning with:

```text

```

That indicates a directory.

You may also see:

```text

```

which indicates a symbolic link.

A regular file is commonly represented with:

```text
-
```

as the first character.

For example, conceptually:

```text
-rw-r--r--   regular file
drwxr-xr-x   directory
lrwxrwxrwx   symbolic link
```

Do not try to interpret the remaining permission characters yet.

That belongs to the permissions labs.

For now, read only the first character.

# 12. Symbolic links can point somewhere else

On modern Ubuntu systems, you may find entries such as:

```text
/bin
/sbin
/lib
```

implemented as symbolic links.

Check:

```bash
ls -ld /bin
```

You may see output containing something similar to:


The exact result depends on your distribution and filesystem layout.

The arrow indicates that `/bin` is a symbolic link whose target is another location.

# 13. Important directories you should begin recognizing

You do not need to memorize every Linux directory, but there are several locations you will see repeatedly.

## `/etc`

Commonly contains system-wide configuration.

Inspect it:

```bash
ls /etc
```

Do not modify anything.

---

## `/home`

Commonly contains home directories for regular users.

Inspect:

```bash
ls /home
```

Depending on the environment, you may see your username and possibly other users.

---

## `/var`

Contains variable data that changes while the system operates.

It commonly includes things such as logs, caches and application state.

Inspect:

```bash
ls /var
```

You may see directories such as:

```text
log
cache
lib
tmp
```

Exact contents vary.

---

## `/tmp`

Used for temporary files.

Inspect:

```bash
ls -la /tmp
```

Do not delete anything simply because it is in `/tmp`.

Temporary does not mean "safe to remove at any moment."

---

## `/usr`

Contains a large amount of installed user-space software and related data.

Inspect:

```bash
ls /usr
```

You may see directories such as:

```text
bin
lib
sbin
share
```

---

## `/opt`

Often used for optional or third-party software.

Run:

```bash
ls -la /opt
```

It may contain very little on a fresh installation.

That is not an error.

---

## `/root`

This is commonly the home directory of the `root` administrative user.

It is not the same thing as:

```text
/
```

Remember:

```text
/       filesystem root
/root   root user's home directory
```

As a standard user, you may not have permission to inspect `/root`.

That is expected.

---

## `/dev`

Contains device nodes and other device-related filesystem objects.

Inspect only:

```bash
ls /dev
```

You will encounter block and character devices later when working with storage and system administration.

---

## `/proc`

`/proc` is different from an ordinary directory full of persistent files.

It is a virtual filesystem through which the kernel exposes information about processes and system state.

Inspect:

```bash
ls /proc
```

You will probably notice many numeric directory names.

Those commonly correspond to process IDs.

You do not need to investigate them deeply yet.

---

## `/sys`

`/sys` is another virtual filesystem that exposes information about devices, drivers and kernel objects.

Inspect:

```bash
ls /sys
```

Again, do not modify anything.

At this point, simply recognize that not every filesystem path represents data stored on disk in the ordinary sense.

---

# 14. Build a mental map, not a memorized list

At this stage, this level of recognition is enough:

```text
/        top of the filesystem
/etc     system configuration
/home    regular user home directories
/root    root user's home directory
/var     changing system/application data
/tmp     temporary files
/usr     installed user-space software and data
/opt     optional software
/dev     device-related objects
/proc    process and kernel information
/sys     kernel/device information
```

You will return to these locations repeatedly throughout Linux World.

Their meaning will become more familiar through use.

# 15. Hidden files are still files

You already saw hidden entries in JUN-001.

Return to your home directory:

```bash
cd
```

Run:

```bash
ls
```

Then:

```bash
ls -a
```

You may see names such as:

```text
.bashrc
.profile
.ssh
```

Linux conventionally treats names beginning with `.` as hidden from a normal `ls` listing.

They are not stored in a special hidden-files area.

The dot is simply part of the name.

For example:

```text
.bashrc
```

is a filename beginning with a dot.

This matters because many applications store configuration in hidden files and directories inside your home directory.

# 16. Inspect hidden entries more closely

Run:

```bash
ls -la ~
```

Look for entries beginning with `.`.

Choose one that exists on your system and inspect it with:

```bash
file ~/.bashrc
```

if `.bashrc` exists.

You can also inspect its metadata:

```bash
stat ~/.bashrc
```

If your environment does not contain `.bashrc`, choose another existing hidden file rather than assuming something is wrong.

The general process is:

```text
find the object
    ↓
identify its path
    ↓
inspect its type
    ↓
inspect its metadata
```

# 17. Linux filenames are case-sensitive

Linux normally treats case as significant in filenames.

These names can refer to three different objects:

```text
report
Report
REPORT
```

Likewise:

```text
notes.txt
Notes.txt
NOTES.TXT
```

are not automatically the same name.

You saw the same principle with commands in JUN-002.

This becomes important when working with paths.

If documentation tells you to inspect:

```text
/etc/hostname
```

typing:

```text
/etc/HOSTNAME
```

does not normally refer to the same object.

---

# 18. Filenames can contain spaces

Linux filenames can contain spaces.

For example, a valid filename could be:

```text
server notes.txt
```

That introduces an important shell issue.

The shell normally uses spaces to separate parts of a command.

So if you eventually work with a file whose name contains spaces, the shell needs a way to understand that the spaces belong to one filename rather than separating multiple arguments.

You will learn shell quoting and escaping in more detail later.

For now, just recognize that spaces are possible and that they require care.

This is also one reason simple, predictable filenames are usually easier to work with from the command line.

---

# 19. Some characters deserve extra care

Linux permits many characters in filenames, but that does not mean every possible filename is convenient.

Names beginning with:

```text
-
```

can be particularly awkward because many commands interpret values beginning with `-` as options.

Names containing spaces, shell metacharacters or unusual punctuation can also require additional care.

As you begin creating your own files in the next lab, prefer clear names such as:

```text
server-notes.txt
backup-config
application-logs
lab-results.txt
```

rather than unnecessarily complicated names.

This is not because Linux cannot handle more complex names.

It is because predictable names make command-line work easier and reduce avoidable mistakes.

# 20. The path tells you where the object lives

Suppose you are given:

```text
/var/log
```

You should already recognize this as an absolute path because it begins with `/`.

Now suppose you are in:

```text
/var
```

and someone refers to:

```text
log
```

That can be a relative path to the same directory.

Verify it yourself:

```bash
cd /var
```

Then:

```bash
pwd
```

Now inspect:

```bash
ls -ld log
```

Then:

```bash
ls -ld /var/log
```

Both refer to the same location in this situation.

One uses a relative path.

The other uses an absolute path.

Return home when finished:

```bash
cd
```

# 21. A directory can contain another directory

This sounds obvious, but it is central to understanding Linux paths.

Consider:

```text
/var/log
```

`var` is a directory beneath `/`.

`log` is a directory beneath `/var`.

You can inspect each level:

```bash
ls -ld /var
```

Then:

```bash
ls -ld /var/log
```

You can also inspect the contents of `/var`:

```bash
ls /var
```

and see whether `log` appears there.

This relationship is what creates the hierarchy you navigate with `cd`.

# 22. Do not confuse an object with its contents

This distinction is worth practicing.

Run:

```bash
ls -ld /var
```

This asks for information about `/var`.

Now:

```bash
ls -l /var
```

This asks for a long listing of what is inside `/var`.

The difference between:

```text
the directory
```

and:

```text
the contents of the directory
```

becomes important when you start working with permissions, ownership, storage usage and troubleshooting.

# 23. Investigate an unfamiliar path

Suppose somebody tells you:

> Check `/var/log`.

You know the path, but imagine you know nothing else about it.

A reasonable first investigation could be:

```bash
ls -ld /var/log
```

Then:

```bash
file /var/log
```

Then:

```bash
stat /var/log
```

Then:

```bash
ls /var/log
```

Each command answers a slightly different question.

`ls -ld` helps you inspect the directory entry.

`file` helps identify what kind of object it is.

`stat` gives you metadata.

`ls /var/log` shows what is inside it, if your user can list the directory.

This is more useful than immediately making assumptions based on the path name.

# 24. What happens when a path does not exist?

Run:

```bash
ls /this-path-should-not-exist
```

You should receive an error similar to:

```text
ls: cannot access '/this-path-should-not-exist': No such file or directory
```

Exact wording can vary.

What do you know from that message?

The requested path could not be found as written.

That does not automatically tell you why.

Possible causes include:

* The path was typed incorrectly.
* The capitalization is wrong.
* A parent directory does not exist.
* The object has a different name.
* You made an incorrect assumption about where it should be.

When working with a relative path, your current directory can also be the problem.

# 25. Investigate instead of immediately correcting

Return home:

```bash

```

Confirm:

```bash
pwd
```

Now deliberately run:

```bash

```

Unless your home directory happens to contain an entry named `etc`, the command should fail.

Why?

You asked for:

```text
etc
```

which is a relative path.

Linux looked for `etc` relative to your current directory.

But the system configuration directory you probably intended is:

```text
/etc
```

Try:

```bash

```

Now it works.

This is not an `ls` problem.

It is a path problem.

That distinction matters.

# 26. File or directory?

Now deliberately try:

```bash
cd /etc/hostname
```

On a typical Ubuntu system, you should receive an error indicating that the path is not a directory.

Why?

`cd` changes directories.

`/etc/hostname` is normally a regular file.

Verify that rather than assuming:

```bash
file /etc/hostname
```

You can also inspect it with:

```bash
ls -l /etc/hostname
```

This is a useful troubleshooting pattern:

```text
Command failed
    ↓
Read the error
    ↓
Inspect the target
    ↓
Confirm what kind of object it is
    ↓
Explain why the operation was inappropriate
```

# 27. Permission errors are different

Try:

```bash
ls /root
```

As a normal user on many Ubuntu systems, you may receive:

```text
Permission denied
```

If your environment allows you to list `/root`, simply note that permissions vary between systems and continue.

Compare the meaning of these failures:

```text
No such file or directory
```

and:

```text
Permission denied
```

They are not the same problem.

`No such file or directory` tells you the requested path could not be found as specified.

`Permission denied` tells you the object may exist, but your current access does not permit the requested operation.

You will study Linux permissions properly in JUN-007.

For now, the important habit is reading the actual error before deciding what happened.

---

# 28. Do not reach for `sudo` automatically

If:

```bash

```

returns:

```text
Permission denied
```

that does not mean the correct response is automatically:

```text
use sudo
```

You first need to ask whether you actually need access.

In this lab, you do not.

The command was used to demonstrate how a permission failure differs from a missing path.

Good Linux administration includes knowing when **not** to elevate privileges.

# 38. Knowledge Check

Try answering these without looking back first.

### 1. What is the filesystem root?

The filesystem root is `/`, the top of the Linux filesystem hierarchy.

### 2. What is a directory?

A directory is a filesystem object used to organize filesystem entries and form the hierarchy of paths.

### 3. Does a Linux file need an extension?

No. Extensions are useful naming conventions, but a file does not require one.

### 4. Does `.txt` guarantee that a file contains text?

No. A filename can suggest content, but the name alone does not prove what is inside.

### 5. What does `file` help you determine?

It examines a filesystem object and reports the kind of data or object it appears to represent.

### 6. What does `stat` provide?

It displays filesystem metadata about a path, including information such as size, type, inode, ownership, permissions and timestamps.

### 7. What does the first character of a long `ls` listing commonly indicate?

It helps identify the filesystem object type. For example, `d` indicates a directory, `l` a symbolic link, and `-` a regular file.

### 8. What is a hidden file in Linux?

By convention, it is usually a file whose name begins with a dot.

### 9. Where are regular users' home directories commonly stored?

Under `/home`.

### 10. Is `/root` the same as `/`?

No. `/` is the filesystem root. `/root` is commonly the root user's home directory.

### 11. What is `/etc` commonly used for?

System-wide configuration.

### 12. What is `/var` commonly used for?

Variable data that changes as the system operates, including logs, caches and application state.

### 13. Why is `/proc` unusual?

It is a virtual filesystem exposing process and kernel information rather than an ordinary directory of persistent files stored on disk.

### 14. What is the difference between `ls -ld /etc` and `ls -l /etc`?

`ls -ld /etc` displays information about the `/etc` directory entry itself. `ls -l /etc` lists the contents of `/etc` in long format.

### 15. What does `No such file or directory` tell you?

The requested path could not be found as specified. You still need to investigate whether the cause is a typo, incorrect case, wrong location or another path problem.

### 16. What does `Permission denied` tell you?

The requested operation is not allowed under your current access. It is different from the path simply not existing.

### 17. Why does `cd /etc/hostname` normally fail?

Because `/etc/hostname` is normally a regular file and `cd` operates on directories.

### 18. Why should you inspect an object before modifying it?

To confirm that the path exists, identify what kind of object it is and make sure you are targeting the object you actually intend to change.

# 39. Interview Practice

### What is the root directory in Linux?

The root directory is `/`. It is the top of the Linux filesystem hierarchy, and all other filesystem paths exist beneath it.

### What is the difference between a file and a directory?

A regular file stores data. A directory organizes filesystem entries and forms part of the path hierarchy.

### How can you determine what type of data a file contains?

One useful command is:

```bash
file PATH
```

It examines the object and reports the type of data or filesystem object it recognizes.

### How can you inspect detailed metadata for a file?

Use:

```bash
stat PATH
```

### How can you inspect a directory itself rather than list its contents?

One method is:

```bash
ls -ld DIRECTORY
```

### What is a hidden file in Linux?

A hidden file is conventionally one whose name begins with a dot, such as `.bashrc`.

### Are filename extensions required in Linux?

No. Extensions can communicate intent or format, but Linux files do not universally depend on extensions to determine their type.

### What is the difference between `/` and `/root`?

`/` is the top of the filesystem. `/root` is commonly the home directory of the root administrative user.

### What is a symbolic link?

A symbolic link is a filesystem object that refers to another path. Symbolic links are covered in depth later in the Junior curriculum.

### Why is `/proc` described as a virtual filesystem?

Because it exposes process and kernel information through filesystem paths rather than representing ordinary persistent files stored on disk.

### What should you do when a filesystem command fails?

Read the error, verify your current location when relevant, inspect the target path, determine what type of object you are dealing with, and identify the actual cause before changing anything.
