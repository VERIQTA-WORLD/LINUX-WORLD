## 2. Understand What a Subnet Is

An IPv4 address contains 32 bits.

A prefix length tells you how many leading bits identify the network prefix.

Consider:

```text
192.0.2.10/24
```

The `/24` means:

```text
24 bits
→ network prefix

remaining 8 bits
→ host portion
```

Conceptually:

```text
IPv4 address = 32 bits

/24

┌────────────────────────┬────────┐
│ 24 network-prefix bits │ 8 bits │
└────────────────────────┴────────┘
                           host
```

A subnet therefore defines an IPv4 network boundary.

Hosts whose addresses fall inside the same configured subnet can generally treat that subnet as directly connected when the corresponding route exists.

### Why the prefix cannot be ignored

Compare:

```text
192.0.2.10/24
```

and:

```text
192.0.2.10/28
```

The address is identical.

The network boundary is not.

For `/24`:

```text
192.0.2.0
through
192.0.2.255
```

belongs to that subnet.

For the subnet containing `192.0.2.10/28`, the range is:

```text
192.0.2.0
through
192.0.2.15
```

That is a much smaller network.

Therefore:

```text
IP ADDRESS ALONE
≠
ENOUGH TO DETERMINE THE SUBNET
```

You need:

```text
ADDRESS + PREFIX
```

## 3. Connect CIDR Prefixes to Subnet Masks

You will commonly see Linux use CIDR prefix notation:

```text
/24
/25
/26
/27
/28
```

Traditional IPv4 documentation may instead show a subnet mask.

Common examples are:

| Prefix | Subnet Mask | Addresses per ordinary subnet |
|---|---|---:|
| `/24` | `255.255.255.0` | 256 |
| `/25` | `255.255.255.128` | 128 |
| `/26` | `255.255.255.192` | 64 |
| `/27` | `255.255.255.224` | 32 |
| `/28` | `255.255.255.240` | 16 |

The prefix and subnet mask express the same network-boundary concept in different notation.

### Why `/24` maps to `255.255.255.0`

A `/24` has 24 leading network bits set in the mask:

```text
11111111.11111111.11111111.00000000
```

Convert each octet:

```text
11111111
=
255
```

```text
00000000
=
0
```

So:

```text
255.255.255.0
```

### `/26`

A `/26` contains:

```text
24 full network bits
+
2 additional network bits
```

The final octet begins:

```text
11000000
```

which is:

```text
192
```

Therefore:

```text
/26
=
255.255.255.192
```

You do not need to perform long binary calculations for every address.

The goal is to understand why the boundaries exist.

## 4. Calculate Network Boundaries

For junior subnetting, a useful technique is to calculate the **block size** in the octet where the subnet changes.

For these common prefixes:

```text
/25 → block size 128
/26 → block size 64
/27 → block size 32
/28 → block size 16
```

### `/24`

For:

```text
192.0.2.10/24
```

the subnet is:

```text
Network:
192.0.2.0

Broadcast:
192.0.2.255

Conventional host range:
192.0.2.1 – 192.0.2.254
```

---

### `/25`

A `/25` divides the final octet into blocks of 128:

```text
0–127
128–255
```

So:

```text
192.0.2.20/25
```

belongs to:

```text
192.0.2.0/25
```

with:

```text
Network:
192.0.2.0

Broadcast:
192.0.2.127

Conventional host range:
192.0.2.1 – 192.0.2.126
```

But:

```text
192.0.2.200/25
```

belongs to:

```text
192.0.2.128/25
```

---

### `/26`

A `/26` uses blocks of 64:

```text
0–63
64–127
128–191
192–255
```

Consider:

```text
192.0.2.70/26
```

`70` falls inside:

```text
64–127
```

Therefore:

```text
Network:
192.0.2.64

Broadcast:
192.0.2.127

Conventional host range:
192.0.2.65 – 192.0.2.126
```

---

### `/27`

A `/27` uses blocks of 32:

```text
0–31
32–63
64–95
96–127
128–159
160–191
192–223
224–255
```

Consider:

```text
192.0.2.100/27
```

`100` belongs to:

```text
96–127
```

Therefore:

```text
Network:
192.0.2.96

Broadcast:
192.0.2.127

Conventional host range:
192.0.2.97 – 192.0.2.126
```

---

### `/28`

A `/28` uses blocks of 16:

```text
0–15
16–31
32–47
48–63
64–79
80–95
96–111
112–127
...
```

Consider:

```text
192.0.2.83/28
```

`83` falls inside:

```text
80–95
```

Therefore:

```text
Network:
192.0.2.80

Broadcast:
192.0.2.95

Conventional host range:
192.0.2.81 – 192.0.2.94
```

### The repeatable method

For these examples:

```text
1. Identify the prefix.

2. Determine the block size.

3. Find the block containing the host address.

4. First address in the block
   → network address.

5. Last address in the block
   → broadcast address.

6. Addresses between them
   → conventional host range.
```

## 5. Understand Network and Broadcast Addresses

In an ordinary IPv4 subnet, two addresses have special meaning.

### Network address

The first address identifies the subnet itself.

For:

```text
192.0.2.64/26
```

the network address is:

```text
192.0.2.64
```

### Broadcast address

The final address is the directed broadcast address for that ordinary IPv4 subnet.

For:

```text
192.0.2.64/26
```

the broadcast address is:

```text
192.0.2.127
```

The conventional host addresses lie between them:

```text
192.0.2.65
through
192.0.2.126
```

### Important scope note

The familiar:

```text
total addresses - 2
```

host calculation is useful for the ordinary IPv4 subnets you are studying here.

Do not turn it into a universal rule for every possible prefix or networking design.

Special cases such as point-to-point `/31` networks exist.

They are outside this junior lab.

## 6. Decide Whether Two Hosts Are in the Same Subnet

Consider:

```text
Host A:
192.0.2.10/24

Host B:
192.0.2.200/24
```

With `/24`, both belong to:

```text
192.0.2.0/24
```

Conceptually:

```text
Host A
192.0.2.10
     │
     ├──── 192.0.2.0/24 ────┤
     │
Host B
192.0.2.200
```

They are in the same IPv4 subnet.

Now change the prefix:

```text
Host A:
192.0.2.10/25

Host B:
192.0.2.200/25
```

The `/25` boundaries are:

```text
192.0.2.0/25
```

and:

```text
192.0.2.128/25
```

So:

```text
192.0.2.10
→ first subnet
```

while:

```text
192.0.2.200
→ second subnet
```

They are no longer in the same subnet.

### Critical lesson

Do not decide:

```text
same first three octets
=
same subnet
```

That works accidentally for many `/24` examples.

It is not the general rule.

Use the prefix.

## 7. Understand Direct Communication and the Default Gateway

Suppose your host is:

```text
192.0.2.10/24
```

Its directly connected subnet is:

```text
192.0.2.0/24
```

Now consider:

```text
192.0.2.50
```

That address belongs to the same `/24`.

Conceptually:

```text
192.0.2.10
     │
     ├──── local subnet ──── 192.0.2.50
```

Linux can treat that network as directly connected when the corresponding connected route exists.

Now consider:

```text
198.51.100.20
```

That destination is outside:

```text
192.0.2.0/24
```

The host needs a route toward that remote network.

A common path is:

```text
HOST
192.0.2.10
     │
     ▼
DEFAULT GATEWAY
192.0.2.1
     │
     ▼
OTHER NETWORKS
     │
     ▼
198.51.100.20
```

### What the gateway does

A gateway is a next-hop router capable of forwarding traffic toward another network.

It does not mean:

```text
gateway
=
final destination
```

The gateway is an intermediate next hop.

### Why the gateway is normally local

If the host must send traffic to its gateway directly, the gateway normally needs to be reachable through one of the host's connected networks.

For:

```text
Host:
192.0.2.10/24
```

a gateway such as:

```text
192.0.2.1
```

is within:

```text
192.0.2.0/24
```

That makes conceptual sense.

A gateway of:

```text
198.51.100.1
```

would not be directly reachable through that `/24` without some additional routing mechanism.

At this level, remember:

```text
DEFAULT GATEWAY
should normally be reachable
through an appropriate local route
```

An entry such as:


```text
INTERFACE

      │
```

An entry beginning:

```text

```


```text

```

```text
via GATEWAY
→ next-hop gateway
```

```text
dev INTERFACE
→ interface used to reach that next hop
```

## 10. Distinguish Gateway, DNS, and Destination

These three concepts are frequently confused.

Suppose an application wants to reach:

```text
app.example.com
```

Conceptually:

```text
app.example.com
      │
      ▼
DNS
      │
      ▼
198.51.100.20
      │
      ▼
ROUTING DECISION
      │
      ▼
DEFAULT GATEWAY
      │
      ▼
REMOTE NETWORK
      │
      ▼
198.51.100.20
```

### DNS server

DNS helps resolve:

```text
app.example.com
```

to an address.

### Default gateway

The gateway helps forward traffic toward remote networks when selected by routing.

### Destination

The destination is the host or endpoint the application ultimately wants to reach.

Therefore:

```text
DNS SERVER
≠
DEFAULT GATEWAY
```

and:

```text
DEFAULT GATEWAY
≠
REMOTE DESTINATION
```

A home router may perform several functions on one device, which can make these concepts look identical.

The functions are still different.

## 11. Troubleshoot Subnet and Gateway Mistakes

Consider a host configured as:

```text
IP:
192.0.2.10/26
```

A `/26` uses blocks of:

```text
64
```

The host belongs to:

```text
192.0.2.0/26
```

with ordinary address boundaries:

```text
Network:
192.0.2.0

Broadcast:
192.0.2.63
```

Now someone configures the gateway as:

```text
192.0.2.100
```

Where does `100` belong?

The `/26` blocks are:

```text
0–63
64–127
128–191
192–255
```

So:

```text
192.0.2.100
```

belongs to:

```text
192.0.2.64/26
```

not:

```text
192.0.2.0/26
```

Under the ordinary directly connected gateway model, that is a configuration inconsistency worth investigating.

### Common mistakes

**Ignoring the prefix**

```text
192.0.2.10
192.0.2.200
```

do not automatically belong to the same subnet.

---

**Assuming `/24` everywhere**

Real networks may use:

```text
/16
/20
/23
/24
/25
/26
/27
/28
```

and many other prefixes.

---

**Using the network address as an ordinary host address**

In a conventional IPv4 subnet, the network address identifies the subnet.

---

**Using the broadcast address as an ordinary host address**

In an ordinary broadcast-capable IPv4 subnet, the directed broadcast address has a special role.

---

**Assuming the gateway must end in `.1`**

No.

`.1` is a common convention.

It is not a networking law.

A valid gateway could use another usable address according to the network design.

---

**Assuming the gateway must be the first usable address**

Again, no.

That is a design convention in some environments.

---

**Assuming DNS failure means the gateway is wrong**

No.

DNS and routing are different layers.

---

**Changing the gateway before inspecting the routing table**

Do not do this.

Start with:

```bash
ip route
```

and gather evidence.

### Knowledge Check

1. **What does an IPv4 subnet represent?**  
   A network boundary defined by an IPv4 address and prefix/mask.

2. **What does `/24` mean?**  
   The first 24 bits form the network prefix, leaving 8 bits outside that prefix.

3. **What subnet mask corresponds to `/24`?**  
   `255.255.255.0`.

4. **What subnet mask corresponds to `/26`?**  
   `255.255.255.192`.

5. **What is the block size of a `/26` in the final octet?**  
   64.

6. **For `192.0.2.70/26`, what is the network address?**  
   `192.0.2.64`.

7. **What is its broadcast address?**  
   `192.0.2.127`.

8. **What is its conventional host range?**  
   `192.0.2.65` through `192.0.2.126`.

9. **Can you determine whether two IPv4 addresses are in the same subnet by comparing only their first three octets?**  
   No. You must consider the prefix.

10. **What is a default gateway?**  
    A next-hop router commonly used to forward traffic toward destinations not reached through a more specific route.

11. **Must a default gateway always use `.1`?**  
    No.

12. **Is a default gateway the same as a DNS server?**  
    No. Routing and name resolution are different functions.

13. **Does every remote destination automatically use the default route?**  
    No. A more specific route may exist.

14. **Why should the gateway normally be reachable through a connected network?**  
    The host needs a valid way to reach the next hop before that next hop can forward traffic onward.

15. **What command shows the Linux IPv4 routing table?**  
    `ip route`.

### Interview Practice

#### What is a subnet?

A subnet is an IP network boundary defined by a network prefix. For IPv4, the prefix determines which address bits identify the network and which remain for addresses within that subnet.

#### What does `192.168.10.25/24` mean?

`192.168.10.25` is the IPv4 address and `/24` is the prefix length. In this case, the corresponding subnet is `192.168.10.0/24`.

#### How do you determine whether two hosts are in the same subnet?

I use each host's IP address and prefix to determine the network each address belongs to. If the relevant network prefixes match, they are in the same subnet for that addressing context.

#### What is the purpose of a default gateway?

The default gateway is typically the next-hop router used by the default route when no more specific route matches a destination.

#### Does traffic to another host in the same subnet normally need to go through the default gateway?

No. When a directly connected route applies, the host can communicate over that local network without sending the traffic to the default gateway as the next hop.

#### Does a gateway have to be `x.x.x.1`?

No. `.1` is a common convention, but the gateway can use another appropriate address according to the network design.

#### How would you inspect the default gateway on Linux?

I would use:

```bash
ip route
```

and inspect the route beginning with `default`, including its `via` next hop and interface.

#### A server has the correct IP address but cannot reach remote networks. What would you check next?

I would confirm the prefix and connected network, inspect the routing table and default route, and verify that the configured next hop makes sense for the host's directly reachable networks before changing anything.

```text
IP ADDRESS + PREFIX
        │
        ▼
DETERMINE SUBNET
        │
        ▼
DESTINATION
        │
        ▼
IS IT DIRECTLY REACHABLE?
      ┌─┴─┐
     YES  NO
      │    │
      ▼    ▼
 CONNECTED   CHECK ROUTES
 NETWORK         │
                 ▼
           DEFAULT ROUTE
           IF APPLICABLE
                 │
                 ▼
              GATEWAY
                 │
                 ▼
           OTHER NETWORKS
```

And keep these distinctions clear:

```text
IP ADDRESS
≠
SUBNET
```

```text
ADDRESS
≠
PREFIX
```

```text
SAME FIRST THREE OCTETS
≠
AUTOMATICALLY SAME SUBNET
```

```text
DEFAULT GATEWAY
≠
DNS SERVER
```

```text
DEFAULT GATEWAY
≠
FINAL DESTINATION
```

```text
REMOTE DESTINATION
≠
AUTOMATICALLY DEFAULT ROUTE
```

The correct habit is:

```text
ADDRESS
   +
PREFIX
   ↓
CALCULATE NETWORK
   ↓
COMPARE DESTINATION
   ↓
INSPECT ROUTING
   ↓
IDENTIFY NEXT HOP
```
