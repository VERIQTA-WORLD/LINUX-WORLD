This is an **inspection-only** lab.

Do not run commands that change interface state such as:



- Netplan configuration;

## 3. Understand Linux Interface Names

Historically, Ethernet interfaces were commonly named:

```text id="v5n1d6"
eth0
eth1
eth2
```

You may still encounter those names.

Modern Linux systems can also use predictable interface names such as:

```text id="r9y3vf"
eno1
ens3
enp0s3
```

Wireless interfaces may use names beginning with forms such as:

```text id="dchb3f"
wl...
```

Virtualized environments may expose names such as:

```text id="w7mh1u"
eth0
ens3
enp0s3
```

depending on platform and configuration.

### Why you should not hard-code assumptions

A command such as:

```text id="oxshru"
ip addr show eth0
```

fails if the machine's interface is actually:

```text id="8i6zhr"
ens3
```

Therefore, the safer habit is:

```text id="66rksv"
DISCOVER FIRST
```

with:

```bash id="73bxbm"
ip link
```

then inspect the actual interface name.

### Engineer Note

An interface name is an operating-system identifier.

It does not by itself prove:

- whether the interface is physical;
- whether it is virtual;
- whether it reaches the Internet;
- whether it has an IP address;
- whether it is currently carrying application traffic.

Treat the name as one piece of evidence.

## 4. Inspect the Loopback Interface

Run:

```bash id="u6sg5d"
ip link show lo
```

Then:

```bash id="o96j0x"
ip addr show lo
```

The interface:

```text id="a72pn7"
lo
```

is the loopback interface.

You will commonly see:

```text id="mls3qj"
127.0.0.1/8
```

and:

```text id="e73fw2"
::1/128
```

although you should always rely on the actual host output.

### Why loopback exists

Loopback allows communication through the local networking stack without sending traffic onto an external network.

Conceptually:

```text id="p17t4h"
APPLICATION A
      │
      ▼
  LOOPBACK
      │
      ▼
APPLICATION B
ON SAME HOST
```

### Loopback is a real interface

Do not dismiss:

```text id="jydjvt"
lo
```

as fake or irrelevant.

Linux treats it as a network interface with its own properties and addresses.

### Important distinction

```text id="3q1eum"
lo
≠
Ethernet adapter
```

but:

```text id="lnllsl"
lo
=
network interface
```

Its purpose is local-host networking rather than communication over an external link.

## 5. Understand Interface Flags and State

Run:

```bash id="0cuvlf"
ip link
```

You may see flags such as:

```text id="w3z8by"
UP
LOWER_UP
BROADCAST
MULTICAST
LOOPBACK
```

These flags describe different interface properties.

Do not treat them as interchangeable.

### `UP`

At a junior level:

```text id="kzlnh9"
UP
→ interface has been administratively enabled
```

It means Linux has the interface configured in an enabled administrative state.

It does **not** prove:

```text id="4j68ba"
Internet works
```

It does not prove:

```text id="q4gm6w"
DNS works
```

It does not prove:

```text id="4fuz1n"
a remote server is reachable
```

---

### `LOWER_UP`

On interfaces where it applies, `LOWER_UP` indicates that the lower layer is reporting an operationally usable link condition.

For an Ethernet-like interface, this can reflect underlying link availability.

Conceptually:

```text id="f16qfs"
UP
→ administratively enabled
```

```text id="tm0b0c"
LOWER_UP
→ lower-layer/link condition available
```

The exact interpretation can vary with interface type.

---

### `BROADCAST`

This indicates that the interface supports broadcast behavior.

You will encounter broadcast addressing more naturally when studying IPv4 and subnets.

---

### `MULTICAST`

This indicates support for multicast behavior.

Detailed multicast administration is outside this junior lab.

---

### `LOOPBACK`

This identifies loopback behavior.

You should expect this flag on:

```text id="oyjtyx"
lo
```

---

## Do not reduce interface health to one flag

This reasoning is weak:

```text id="h4aswi"
UP
 ↓
network works
```

A better model is:

```text id="1asof7"
INTERFACE EXISTS
      │
      ▼
ADMINISTRATIVELY ENABLED?
      │
      ▼
LINK/LOWER LAYER AVAILABLE?
      │
      ▼
ADDRESS CONFIGURED?
      │
      ▼
ROUTE AVAILABLE?
      │
      ▼
NAME RESOLUTION, IF NEEDED?
      │
      ▼
REMOTE SERVICE AVAILABLE?
```

JUN-045 focuses on the first parts of that chain.

## 7. Understand the MAC Address

For Ethernet-like interfaces, `ip link` may show:

```text id="9cbz8c"
link/ether
```

followed by a value resembling:

```text id="35m0gr"
52:54:00:12:34:56
```

This is a MAC address.

### Junior mental model

Think:

```text id="50mqzy"
MAC ADDRESS
      │
      ▼
LINK-LAYER ADDRESS
      │
      ▼
USED IN LOCAL-LINK NETWORKING
```

### MAC address is not an IP address

Compare:

```text id="75j9r0"
52:54:00:12:34:56
```

with:

```text id="7xf4uw"
192.0.2.10
```

The first resembles a MAC address.

The second resembles an IPv4 address.

They serve different purposes.

### MAC addresses may be virtual

Do not assume every MAC address came from a physical network card burned into hardware.

Virtual machines, containers, bridges, and other software-defined networking systems can use software-assigned MAC addresses.

Therefore:

```text id="mnl5z8"
MAC ADDRESS PRESENT
≠
PHYSICAL NIC PROVEN
```

### Do not change it

Linux allows interface properties to be modified, including link-layer addresses in appropriate circumstances.

That is outside this lab.

You are identifying, not changing.

## 8. Understand MTU

Run:

```bash id="80t1dm"
ip link
```

You may see:

```text id="d0bls1"
mtu 1500
```

The acronym:

```text id="f92ch3"
MTU
```

means:

```text id="26mg42"
Maximum Transmission Unit
```

At a junior level, MTU describes the maximum size of an IP packet that can be carried over an interface without requiring fragmentation at that interface's IP layer, subject to protocol and path behavior.

A common Ethernet MTU is:

```text id="5r66ei"
1500 bytes
```

but do not assume every interface uses 1500.

Loopback often uses a much larger MTU.

Virtual networks, tunnels, VPNs, cloud networks, and specialized environments can use different values.

### Inspect two interfaces

Run:

```bash id="u84dfd"
ip link show lo
```

Then inspect your selected interface:

```bash id="96kr5u"
ip link show INTERFACE
```

Compare:

```text id="m6vjjh"
Loopback MTU:

Selected interface MTU:
```

They may differ significantly.

### Why MTU matters

Incorrect MTU assumptions can contribute to problems involving:

- packet delivery;
- tunnels;
- VPNs;
- encapsulation;
- some application connections.

Detailed MTU troubleshooting belongs later.

For now:

```text id="oyrbyu"
MTU
→ important interface property
```

Do not change it in this lab.

## 9. Connect Interfaces to IP Addresses

Now inspect:

```bash id="73c1oh"
ip addr
```

This command includes both:

```text id="yiyolz"
interface information
```

and:

```text id="2g2f25"
address information
```

Choose your non-loopback interface:

```bash id="1x6bgc"
ip addr show INTERFACE
```

Look for:

```text id="8vef4m"
inet
```

and:

```text id="v52pr6"
inet6
```

### IPv4

A line may conceptually resemble:

```text id="gxrt3j"
inet 192.0.2.10/24
```

The:

```text id="e0af7s"
192.0.2.10
```

portion is the IPv4 address.

The:

```text id="f3jlsq"
/24
```

is the prefix length.

You will study it formally in the subnet labs.

---

### IPv6

A line may begin:

```text id="e9z0kh"
inet6
```

An interface may have:

- no IPv6 addresses;
- one IPv6 address;
- multiple IPv6 addresses.

Likewise, an interface can have multiple IPv4 addresses.

### Critical concept

```text id="wlnn0q"
ONE INTERFACE
      │
      ├── IPv4 address
      ├── another IPv4 address
      ├── IPv6 address
      └── another IPv6 address
```

Therefore:

```text id="ztpd7f"
INTERFACE
≠
ONE IP ADDRESS
```

### An interface can also have no IP address

An interface can exist in Linux without having an IP address assigned.

Therefore:

```text id="12uxc9"
INTERFACE EXISTS
≠
IP ADDRESS MUST EXIST
```

This distinction is important during troubleshooting.

## 10. Use `/sys/class/net` as Another Interface View

Linux exposes interface information through sysfs.

List:

```bash id="x0ryqw"
ls /sys/class/net
```

You should see interface names.

Compare with:

```bash id="a9qlps"
ip link
```

The names should correspond to interfaces known to the kernel.

### Inspect one interface

Replace `INTERFACE` with your actual interface name:

```bash id="hzfnva"
ls /sys/class/net/INTERFACE
```

You will see files and links representing interface properties.

You do not need to understand every entry.

### Read the MAC address

```bash id="j8cmks"
cat /sys/class/net/INTERFACE/address
```

Compare with:

```bash id="mgfy7n"
ip link show INTERFACE
```

Do they agree?

They should describe the same link-layer address.

### Read the MTU

```bash id="ytb3ew"
cat /sys/class/net/INTERFACE/mtu
```

Compare with:

```bash id="2blt03"
ip link show INTERFACE
```

### Read the operational state

```bash id="lmgvhw"
cat /sys/class/net/INTERFACE/operstate
```

You might see:

```text id="n6iv4g"
up
```

or another state.

### Why this matters

You are learning an important Linux principle:

```text id="1kqpd4"
SAME KERNEL STATE
      │
      ├── command-line tools
      │
      └── kernel-exposed virtual filesystems
```

`ip` provides a convenient administrative view.

`/sys/class/net` exposes kernel interface objects and attributes.

## 11. Inspect Interface Statistics

Network interfaces maintain counters.

Run:

```bash id="h6k1dw"
ip -s link
```

The:

```text id="r8n99x"
-s
```

option displays statistics.

You may see sections for:

```text id="h0jvyu"
RX
```

and:

```text id="f0vvb6"
TX
```

Think:

```text id="92zpmw"
RX
→ receive
```

```text id="b9x2qa"
TX
→ transmit
```

Fields may include counts for:

```text id="5f0d4q"
bytes
packets
errors
dropped
```

depending on the interface and tool output.

### Inspect one interface

```bash id="fbnprr"
ip -s link show INTERFACE
```

Record:

```text id="kncyye"
RX bytes:

RX packets:

RX errors:

RX dropped:

TX bytes:

TX packets:

TX errors:

TX dropped:
```

### What counters can tell you

Counters provide evidence about interface activity.

For example:

```text id="oh92qp"
RX packets increasing
```

means the interface has received traffic.

```text id="du35up"
TX packets increasing
```

means it has transmitted traffic.

Error or drop counters can become important during troubleshooting.

### What counters cannot tell you alone

This reasoning is too strong:

```text id="n1kk3h"
RX errors > 0
        ↓
network currently broken
```

A counter may have accumulated since:

- boot;
- interface creation;
- counter reset;
- another relevant lifecycle point.

You need context and change over time.

Similarly:

```text id="epas47"
0 errors
```

does not prove every application can communicate successfully.

Interface counters are evidence, not the entire diagnosis.

## 12. Avoid Common Interface Misdiagnoses

### Mistake 1 — `UP` means networking works

No.

`UP` tells you about administrative interface state.

You still need:

```text id="t22b86"
link condition
addressing
routing
DNS where required
transport
remote service
```

to establish end-to-end communication.

---

### Mistake 2 — `DOWN` always means broken hardware

No.

An interface may simply be administratively disabled or unused.

Investigate before diagnosing hardware.

---

### Mistake 3 — Every interface is physical

No.

Linux can expose many virtual interface types.

---

### Mistake 4 — Every interface has a MAC address in the same Ethernet form

No.

Different interface/link types can expose different link-layer behavior.

Do not force the Ethernet model onto every interface.

---

### Mistake 5 — Every interface must have an IP address

No.

An interface can exist without IP configuration.

---

### Mistake 6 — One interface can have only one IP address

No.

An interface can have multiple IPv4 and IPv6 addresses.

---

### Mistake 7 — An IP address belongs permanently to a physical NIC

Not necessarily.

Addresses can be dynamically assigned, moved, replaced, or associated with virtual networking structures.

---

### Mistake 8 — A MAC address proves physical hardware exists

No.

Virtual interfaces can have MAC addresses.

---

### Mistake 9 — `state UP` proves the Internet is reachable

No.

Interface state is only one layer of the network path.

---

### Mistake 10 — An interface name proves its role

No.

A name such as:

```text id="3r7avw"
eth0
```

does not prove it is:

```text id="99jvtb"
the Internet interface
```

Use:

```bash id="00f7oq"
ip route
```

and later networking tools to establish its role.

---


## 14. Knowledge Check, Interview Practice, and Completion

### Knowledge Check

1. **What is a Linux network interface?**  
   A networking endpoint represented by the Linux kernel through which network communication can occur.

2. **Must every network interface represent physical hardware?**  
   No. Linux supports both physical and virtual interfaces.

3. **What command lists Linux network interfaces?**  
   `ip link`.

4. **What is `lo`?**  
   The loopback interface used for local-host networking.

5. **What does the `UP` flag indicate at a junior level?**  
   That the interface is administratively enabled.

6. **What does `LOWER_UP` indicate?**  
   Where applicable, it indicates that the lower layer is reporting an operationally available link condition.

7. **Does `UP` prove remote connectivity?**  
   No.

8. **What does MTU mean?**  
   Maximum Transmission Unit, an interface property related to the maximum IP packet size handled on that interface without fragmentation at that interface's IP layer, subject to protocol and path behavior.

9. **What does `link/ether` indicate?**  
   Ethernet-style link-layer addressing information.

10. **Can a virtual interface have a MAC address?**  
    Yes.

11. **Can one interface have multiple IP addresses?**  
    Yes. It can have multiple IPv4 and/or IPv6 addresses.

12. **Can an interface exist without an IP address?**  
    Yes.

13. **What does `ip -s link` add to interface inspection?**  
    Receive/transmit counters including packet, byte, error, and drop information where reported.

14. **What is `/sys/class/net` useful for?**  
    It exposes kernel network-interface objects and attributes through sysfs.

15. **Does zero interface errors prove an application can reach a remote service?**  
    No. Interface counters cover only part of the end-to-end networking path.

#### How would you list all network interfaces on Linux?

I would use:

```bash id="c03s0g"
ip link
```

I could then inspect a specific interface with:

```bash id="lhbg9q"
ip link show INTERFACE
```

---

#### What is the difference between `ip link` and `ip addr`?

`ip link` focuses on interface/link-layer properties such as interface state, MTU, and link-layer addresses. `ip addr` also displays IP address assignments associated with interfaces.

---

#### What is the difference between `UP` and `LOWER_UP`?

`UP` represents the interface's administrative enabled state. `LOWER_UP`, where applicable, indicates that the underlying link layer is reporting an operationally available condition. Neither alone proves end-to-end application connectivity.

---

#### Can an interface be UP but still have no network connectivity?

Yes. It might lack an appropriate IP address, route, gateway, DNS configuration, upstream connectivity, or remote service availability.

---

#### Can a Linux interface have more than one IP address?

Yes. An interface can have multiple IPv4 addresses, multiple IPv6 addresses, or both.

---

#### What is MTU?

MTU is the Maximum Transmission Unit. It describes an interface's packet-size limit at the relevant network layer. MTU mismatches or path constraints can contribute to connectivity problems, especially with encapsulation or tunnels.

---

#### How would you inspect interface errors?

I would use:

```bash id="4zgvlx"
ip -s link show INTERFACE
```

and examine receive and transmit error/drop counters. I would interpret those counters with context rather than diagnosing a problem from a single nonzero value.

---

#### How can you tell whether an interface is the host's default outbound interface?

I would not infer it from the interface name. I would inspect:

```bash id="q5zgnv"
ip route
```

and determine which interface is referenced by the default route.
