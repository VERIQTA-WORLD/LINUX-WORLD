# 02. Project Scenario

VERIQTA Commerce operates a business-critical web application on Linux.

The original application started on one server.

Growth created predictable problems:

* one server is a single point of failure;
* configuration differs between machines;
* engineers make manual changes;
* database recovery has never been tested;
* logs exist only on individual machines;
* there is no centralized monitoring;
* backups exist but restores are rarely tested;
* network access is broader than necessary;
* operational documentation is incomplete;
* nobody knows the actual recovery time;
* failures are detected by users;
* production changes are difficult to reproduce.

You have been assigned to redesign the environment.

The business requires:

```text
redundant web infrastructure
redundant application infrastructure
database replication
centralized monitoring
centralized logging
controlled administrative access
host firewalls
configuration automation
backup automation
tested recovery
documented RTO/RPO
failure testing
operational runbooks
architecture documentation
```

The goal is not to claim that a small VM lab is equivalent to a real enterprise datacenter.

The goal is to demonstrate the engineering practices used to design and operate production Linux infrastructure.

# 08. Architecture

## 8.1 Failure domains

Identify failures before building.

### LB01 failure

Impact:

```text
customer entry point unavailable
```

This remains a deliberate lab limitation.

A real production design should normally remove this single point of failure with multiple load balancers, virtual IPs, managed load balancing, anycast, or another HA mechanism.

Do not hide this limitation.

---

### WEB01 failure

Expected:

```text
LB01 removes/fails around WEB01
WEB02 continues serving requests
```

---

### APP01 failure

Expected:

```text
web tier routes to APP02
```

---

### DB01 failure

Expected:

```text
application writes stop until controlled database recovery/failover occurs
```

Database failover will initially be **operator-controlled**.

Do not create unsafe automatic PostgreSQL promotion merely to claim automatic failover.

---

### OBS01 failure

Expected:

```text
application remains available
monitoring/log-query capability is degraded
```

Observability should not sit in the customer request path.

---

### BACKUP01 failure

Expected:

```text
production continues
new remote backups fail
```

That failure must become visible.

---

## 8.2 Trust zones

Conceptually divide infrastructure into:

```text
EDGE
WEB
APPLICATION
DATABASE
MANAGEMENT
OBSERVABILITY
BACKUP
DR
```

Even though the lab uses one virtual subnet, firewall policy will model these boundaries.

## 12.5 Create application

Create:

```text
application/app.py
```

with:

```python
#!/usr/bin/env python3

import json
import os
import socket
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

HOST = "0.0.0.0"
PORT = 8080


class Handler(BaseHTTPRequestHandler):

    def send_json(self, status, payload):
        body = json.dumps(payload).encode()

        self.send_response(status)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()

        self.wfile.write(body)

    def do_GET(self):

        if self.path == "/health":
            self.send_json(
                200,
                {
                    "status": "healthy",
                    "host": socket.gethostname()
                }
            )
            return

        if self.path == "/orders":
            self.send_json(
                200,
                {
                    "service": "commerce-api",
                    "host": socket.gethostname(),
                    "orders": [
                        {"id": 1001, "status": "paid"},
                        {"id": 1002, "status": "processing"}
                    ]
                }
            )
            return

        self.send_json(404, {"error": "not found"})

    def log_message(self, fmt, *args):
        print(
            "%s - %s" %
            (self.address_string(), fmt % args),
            flush=True
        )


server = ThreadingHTTPServer((HOST, PORT), Handler)
server.serve_forever()
```

Copy to both application servers:

```bash
scp application/app.py \
  app01:/tmp/app.py

```
