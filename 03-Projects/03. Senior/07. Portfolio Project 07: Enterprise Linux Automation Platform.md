# 02. Project Scenario

An organization operates an expanding Linux estate.

Initially it managed five servers manually.

Now it operates dozens of systems and expects continued growth.

Administrators currently perform work such as:

```text
Create users manually.

Copy SSH keys manually.

Install packages manually.

Edit sshd_config manually.

Configure UFW manually.

Install monitoring manually.

Restart services manually.

Check configuration manually.

Patch systems manually.

Investigate configuration drift manually.
```

This produces inconsistent systems.

For example:

```text
WEB01
SSH root login disabled
UFW enabled
node exporter installed
chrony configured

WEB02
SSH root login enabled
UFW enabled
node exporter missing
chrony configured

WEB03
SSH root login disabled
UFW disabled
old package versions
monitoring broken
```

The problem is not simply that administration takes too long.

The larger problem is that nobody can reliably answer:

```text
What should every server look like?

Which systems differ?

Why do they differ?

Who changed them?

Can the intended state be reproduced?

Can 50 new systems receive the same configuration?

Can a failed deployment be stopped before every server is affected?

Can configuration drift be detected?

Can drift be corrected automatically?

Can an unsafe change be rolled back?
```

You have been asked to design an automation platform that makes infrastructure configuration repeatable, testable and auditable.

# 08. Architecture

## 8.1 Control-plane model

AUTOMATION01 is the automation control node.

It stores:

```text
Inventory
Variables
Playbooks
Roles
Templates
Validation scripts
Automation scripts
Encrypted variables
Documentation
```

Managed systems do not require an Ansible daemon.

Management occurs primarily over SSH.

---

## 8.2 Desired state

Instead of saying:

```text
Run apt install nginx.
```

define:

```text
Nginx must be installed.
Nginx must be enabled.
Nginx must be running.
Its configuration must match the approved template.
The configuration must pass validation.
Port 80 must be reachable from the approved network.
```

Automation should converge systems toward that state.

---

## 8.3 Idempotency

A fundamental project requirement is:

```text
First execution:

changed=many


Second execution without infrastructure changes:

changed=0
```

Not every command or third-party component is inherently idempotent.

Where idempotency cannot be guaranteed, document the reason.

---

## 8.4 Blast-radius control

Never think:

```text
Automation makes changes faster.
```

without also thinking:

```text
Automation can break systems faster.
```

The platform therefore implements:

```text
syntax validation
      ↓
linting
      ↓
inventory validation
      ↓
check mode where meaningful
      ↓
small-host test
      ↓
rolling batch
      ↓
post-change verification
      ↓
broader rollout
```

---

## 8.5 Environment model

This lab uses one environment:

```text
lab
```

But structure it so that future environments can become:

```text
inventories/
├── lab/
├── staging/
└── production/
```

without rewriting every role.

## 10.5 Bootstrap managed nodes

Before Ansible can manage a fresh server, it needs an initial access path.

On each managed host, using console or the initial provisioning account:

```bash
sudo adduser automation
```

Add temporary bootstrap sudo:

```bash
sudo usermod -aG sudo automation
```

Create SSH directory:

```bash
sudo install \
  -d \
  -o automation \
  -g automation \
  -m 0700 \
  /home/automation/.ssh
```

Place the contents of:

```text
~/.ssh/automation_ed25519.pub
```

from AUTOMATION01 into:

```text
/home/automation/.ssh/authorized_keys
```

on each managed host.

Then:

```bash
sudo chown \
  automation:automation \
  /home/automation/.ssh/authorized_keys
```

```bash
sudo chmod 0600 \
  /home/automation/.ssh/authorized_keys
```


## 12.10 Build SSH security role

Back up SSH configuration through automation before changing it.

Create:

```bash
cat > roles/security/tasks/main.yml <<'EOF'
---
- name: Ensure OpenSSH server is installed
  ansible.builtin.apt:
    name: openssh-server
    state: present
    update_cache: true
    cache_valid_time: 3600

- name: Ensure SSH drop-in directory exists
  ansible.builtin.file:
    path: /etc/ssh/sshd_config.d
    state: directory
    owner: root
    group: root
    mode: "0755"

- name: Deploy managed SSH security policy
  ansible.builtin.template:
    src: 60-automation-security.conf.j2
    dest: /etc/ssh/sshd_config.d/60-automation-security.conf
    owner: root
    group: root
    mode: "0644"
    validate: "/usr/sbin/sshd -t -f %s"
  notify: Reload SSH

- name: Ensure UFW is installed
  ansible.builtin.apt:
    name: ufw
    state: present

- name: Ensure auditd is installed
  ansible.builtin.apt:
    name: auditd
    state: present

- name: Ensure auditd is enabled and running
  ansible.builtin.service:
    name: auditd
    state: started
    enabled: true
EOF
```

---

## 12.11 Create SSH template

```bash
cat > roles/security/templates/60-automation-security.conf.j2 <<'EOF'
# Managed by Ansible.
# Manual changes may be overwritten.

PermitRootLogin {{ ssh_permit_root_login }}
PasswordAuthentication {{ ssh_password_authentication }}
PubkeyAuthentication yes
PermitEmptyPasswords no
X11Forwarding no
EOF
```

---

## 12.12 Create SSH handler

```bash
cat > roles/security/handlers/main.yml <<'EOF'
---
- name: Reload SSH
  ansible.builtin.service:
    name: ssh
    state: reloaded
EOF
```

The handler runs only when notified by a changed task.

That prevents unnecessary SSH reloads.

## 12.15 Build user-management automation

Create variables:

```bash
cat >> inventories/lab/group_vars/all/main.yml <<'EOF'

managed_users:
  - name: alice
    groups:
      - linux-admins
    shell: /bin/bash

  - name: carol
    groups:
      - linux-admins
    shell: /bin/bash

```

Create task file:

```bash
cat > roles/common/tasks/users.yml <<'EOF'
---
- name: Ensure managed users exist
  ansible.builtin.user:
    name: "{{ item.name }}"
    groups: "{{ item.groups | join(',') }}"
    append: true
    shell: "{{ item.shell }}"
    create_home: true
    state: present
  loop: "{{ managed_users }}"
EOF
```

Include it from common role:

```bash
cat >> roles/common/tasks/main.yml <<'EOF'

- name: Manage Linux users

EOF
```

Validate:

```bash
ansible-playbook \
  playbooks/baseline.yml \
  --syntax-check
```

```bash
ansible-playbook \
  playbooks/baseline.yml
```

## 14.3 Build Python inventory reporter

Create:

```bash
cat > scripts/python/inventory_report.py <<'EOF'
#!/usr/bin/env python3

import json
import subprocess
import sys
from pathlib import Path


def run_inventory():
    command = [
        "ansible-inventory",
        "-i",
        "inventories/lab/hosts.yml",
        "--list",
    ]

    result = subprocess.run(
        command,
        check=True,
        capture_output=True,
        text=True,
    )

    return json.loads(result.stdout)


def main():
    try:
        inventory = run_inventory()
    except subprocess.CalledProcessError as exc:
        print("Inventory command failed.", file=sys.stderr)
        print(exc.stderr, file=sys.stderr)
        return 1
    except json.JSONDecodeError as exc:
        print(f"Inventory returned invalid JSON: {exc}", file=sys.stderr)
        return 1

    hostvars = inventory.get("_meta", {}).get("hostvars", {})

    report = {
        "host_count": len(hostvars),
        "hosts": [],
    }

    for hostname in sorted(hostvars):
        variables = hostvars[hostname]

        report["hosts"].append(
            {
                "hostname": hostname,
                "ansible_host": variables.get("ansible_host"),
                "ansible_user": variables.get("ansible_user"),
            }
        )

    output_path = Path("reports/inventory-report.json")
    output_path.parent.mkdir(parents=True, exist_ok=True)

    output_path.write_text(
        json.dumps(report, indent=2) + "\n",
        encoding="utf-8",
    )

    print(f"Hosts discovered: {report['host_count']}")

    for host in report["hosts"]:
        print(
            f"{host['hostname']:<12} "
            f"{host['ansible_host'] or '-':<16} "
            f"{host['ansible_user'] or '-'}"
        )

    print(f"\nReport written to {output_path}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
EOF
```

Make executable:

```bash
chmod +x \
  scripts/python/inventory_report.py
```

Run:

```bash

```

Inspect:

```bash

```

## 15.5 Security automation principle

Never automate:

```text

Disable AppArmor because deployment failed.

Use curl | bash without verification.
```

Automation should enforce engineering discipline, not automate shortcuts.

```bash
- name: Demonstrate controlled rolling failure
  hosts: webservers
  serial: 1
  any_errors_fatal: true

      ansible.builtin.debug:
        msg: "Processing {{ inventory_hostname }}"

    - name: Inject failure on web02
      ansible.builtin.fail:
        msg: "Controlled failure on web02"
      when: inventory_hostname == "web02"

    - name: Task that should not continue after fatal failure
      ansible.builtin.debug:
        msg: "Post-failure task on {{ inventory_hostname }}"
EOF
```

## sudo failure

Manual:

```bash
ssh \
  -i ~/.ssh/automation_ed25519 \
  automation@192.168.56.21
```

Then:

```bash
sudo -n true
```

Check:

```bash
sudo -l
```

Do not diagnose a privilege-escalation problem as an Ansible connection problem.

---

## Wrong variable

Inspect:

```bash
ansible-inventory \
  --host web01
```

Use:

```bash
ansible-config dump \
  --only-changed
```

Remember that Ansible has variable precedence rules.

Do not create the same variable in many locations without understanding which value wins.

---

## Task always reports changed

Ask:

```text
Is the module idempotent?

Am I using shell/command unnecessarily?

Does the task actually alter something every run?

Should changed_when be defined?

Am I generating nondeterministic content?

Does a template include a timestamp?
```

Do not hide a genuine idempotency problem with:

```yaml
changed_when: false
```

unless the task truly does not modify state.

---

## Handler does not run

Check:

```text
Did the notifying task report changed?

Does notify exactly match the handler?

Was the handler loaded?

Did execution fail before handlers ran?
```

---

## Template breaks service

Inspect rendered candidate.

For SSH use validation before deployment.

For other services, use the application's native configuration validator where available.

The preferred pattern is:

```text
Render candidate
       ↓
Validate candidate
       ↓
Install candidate
       ↓
Notify handler
       ↓
Reload/restart
       ↓
Health check
```
