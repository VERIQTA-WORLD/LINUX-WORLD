# 01. Project Title

## Production Linux Incident Simulation

Build a small production-style Linux service, establish its known-good state, then deliberately inject multiple interacting failures.

The responder must investigate without being told the root cause.

The incident must progress through:

```text

      ↓

      ↓

      ↓

      ↓

      ↓

      ↓
COMPETING HYPOTHESES
      ↓
MITIGATION
      ↓
SERVICE RESTORATION
      ↓
RECOVERY VERIFICATION
      ↓
ROOT-CAUSE ANALYSIS
      ↓
TIMELINE RECONSTRUCTION
      ↓
```

## Incident design

The canonical incident contains four layers.

### Failure A — Storage pressure

Application logging grows unexpectedly and consumes most of the filesystem containing application runtime data/logs.

### Failure B — Application restart instability

The application begins failing because it cannot reliably write required data.

systemd attempts to restart it.

Repeated failures create an unstable service state.

### Failure C — Resource contention

A background workload creates additional memory/I/O pressure.

This produces misleading symptoms and increases application latency.

### Failure D — Secondary proxy symptoms

Because the backend becomes slow or unavailable, the reverse proxy begins returning upstream failures.

The proxy is not the root cause.

That distinction is important.

## 12.3 Build Orders API

Create:

```bash
sudo tee /opt/orders-api/app.py >/dev/null <<'PY'
#!/usr/bin/env python3

import json
import os
import time
from datetime import datetime, timezone
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

HOST = "0.0.0.0"
PORT = 8080
STATE_DIR = "/var/lib/orders-api"
LOG_FILE = "/var/log/orders-api/orders.log"

os.makedirs(STATE_DIR, exist_ok=True)


def timestamp():
    return datetime.now(timezone.utc).isoformat()


def write_log(message):
    with open(LOG_FILE, "a", encoding="utf-8") as log:
        log.write(f"{timestamp()} {message}\n")
        log.flush()
        os.fsync(log.fileno())


class Handler(BaseHTTPRequestHandler):

    def send_json(self, code, payload):
        body = json.dumps(payload).encode()

        self.send_response(code)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()

        self.wfile.write(body)

    def do_GET(self):

        start = time.monotonic()

        if self.path == "/health":
            try:
                test_file = os.path.join(
                    STATE_DIR,
                    ".health-write-test"
                )

                with open(test_file, "w", encoding="utf-8") as f:
                    f.write(timestamp())

                os.remove(test_file)

                self.send_json(
                    200,
                    {
                        "status": "healthy",
                        "host": os.uname().nodename
                    }
                )

            except Exception as exc:
                self.send_json(
                    503,
                    {
                        "status": "unhealthy",
                        "error": str(exc)
                    }
                )

            return

        if self.path == "/orders":

            try:
                write_log(
                    f"request path=/orders "
                    f"client={self.client_address[0]}"
                )

                self.send_json(
                    200,
                    {
                        "orders": [
                            {"id": 1001, "status": "paid"},
                            {"id": 1002, "status": "processing"}
                        ]
                    }
                )

            except Exception as exc:
                self.send_json(
                    500,
                    {
                        "error": str(exc)
                    }
                )

            finally:
                duration = time.monotonic() - start

                try:
                    write_log(
                        f"request_complete "
                        f"path=/orders "
                        f"duration={duration:.6f}"
                    )
                except Exception:
                    pass

            return

        self.send_json(
            404,
            {"error": "not found"}
        )

    def log_message(self, format, *args):
        return


server = ThreadingHTTPServer(
    (HOST, PORT),
    Handler
)

write_log(
    f"orders-api starting host={HOST} port={PORT}"
)

server.serve_forever()
PY
```

# 14. Automation

# Build the Incident Toolkit

## 14.1 Synthetic health checker

On CLIENT01:

```bash
cat > ~/health-check.sh <<'EOF'
#!/usr/bin/env bash

set -u

URL="${1:-http://192.168.56.31/health}"
INTERVAL="${2:-2}"

while true; do

    timestamp="$(date --iso-8601=seconds)"

    result="$(
        curl \
          -sS \
          -o /dev/null \
          --connect-timeout 2 \
          --max-time 6 \
          -w '%{http_code} %{time_total}' \
          "$URL" \
          2>/dev/null
    )"

    rc=$?

    if [[ $rc -ne 0 ]]; then
        echo "$timestamp curl_error=$rc"
    else
        echo "$timestamp $result"
    fi

    sleep "$INTERVAL"

done
EOF
```

# Root-Cause Analysis

Only after stable recovery should you inspect the controller details if you were the responder.


---

## Root cause model

Do not write:

```text
Root cause: disk full.
```

That is too shallow.

Investigate:

### Trigger

What initiated abnormal log growth?

### Failure mechanism

Why did growth become capable of exhausting the filesystem?

### Detection failure

Why was the condition not detected before customer impact?

### Protection failure

Why did the architecture permit unbounded growth?

### Service behavior

Why did application availability depend on that writable filesystem?

### Recovery behavior

How did systemd respond?

### Secondary effects

How did resource pressure alter symptoms?

### Customer manifestation

Why did the customer see 502s?

---

# Canonical Causal Chain

Your measured evidence should allow you to evaluate a chain similar to:

```text
UNBOUNDED LOG GROWTH
        ↓
DEDICATED LOG FILESYSTEM FILLS
        ↓
APPLICATION WRITES FAIL
        ↓
APPLICATION BECOMES UNHEALTHY / UNSTABLE
        ↓
BACKEND AVAILABILITY DEGRADES
        ↓
NGINX CANNOT RELIABLY REACH HEALTHY BACKEND
        ↓
502 / TIMEOUTS
        ↓
CUSTOMER IMPACT
```

Meanwhile:

```text
RESOURCE PRESSURE
        ↓
MEMORY / I/O STALLS
        ↓
HIGHER LATENCY
        ↓
NOISIER INCIDENT SIGNALS
```

The second chain can be a contributing factor without being the primary root cause.

Your evidence determines the final classification.
